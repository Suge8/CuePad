# 手机侧栏进展段收口：两个方案

问题：侧栏进展段那一排有两层分段（项目｜进展，里面又是看板｜会话），看板与会话两颗图标还长得像。
效果图：[方案1.png](方案1.png)（推荐）、[方案2.png](方案2.png)。每块都是现状在上、方案在下，编号贴在被指处旁边。

## 一句话

- **方案 1 进展只剩看板**：同宽屏，手机也去掉进展的会话段。侧栏一排是项目｜进展、项目范围、Cue 头像；已结束的会话进 Cue 页会话条底下的「更早」，点了推入一页。
- **方案 2 三段平级**：两层压成一层，项目｜看板｜会话，只写字不画图标，记住上次那一段。

两个方案共同的：额度从进展那一排挪到项目段末尾那一组（归档、回收站、设置上面），点它原地展开明细；项目范围写成字留在顶上那一排。

## 关键差异

| | 方案 1 | 方案 2 |
|---|---|---|
| 顶上那一排 | 项目｜进展、全部项目 ⌄、Cue 头像 | 项目｜看板｜会话、全部项目 ⌄、Cue 头像 |
| 分段层数 | 一层，两段 | 一层，三段 |
| 在跑、等你的会话 | 只在 Cue 页会话条上 | 会话条上，会话段的「现在」再列一遍 |
| 已结束的会话 | 会话条底下「更早 N」→ 推入「更早」页 | 会话段的「历史」 |
| 新会话 | 推进中行头的 ＋（同待办行头添加任务的 ＋） | 会话列表第一行（同现状） |
| 和宽屏 | 一致 | 手机多一段 |
| iPad 320 窄窗 | 项目｜进展退成图标，范围写成字放得下 | 三段字放得下，范围退成一颗筛选圆钮 |

## 推荐方案 1

1. 两层分段与两颗像的图标是从结构上消失的，不是换个摆法：进展只有看板一件事。
2. 会话段的「现在」与会话条重复：在跑、等你的会话在 Cue 页会话条上一直看得见，同一份东西在两处列。
3. 与宽屏同一套：宽屏的进展页早已只有看板，已结束的在左栏的「更早」，手机也是「更早」，用户只学一次。
4. 方案 2 只是把两层压平：「看板」「会话」仍是两个都在说进展的段，顶上要排三段字，窄窗口里项目范围得退成图标。

方案 1 的代价：看已结束的会话多一步（侧栏回 Cue 页 → 更早）；按项目看会话没有了（「更早」页不按项目筛），只能按项目看看板，或在搜索里搜会话。

## 原来去会话段的入口，方案 1 的落点

- 项目页「⋯」里的「看这个项目的会话」：改成「看这个项目的进展」，项目范围设成它、去看板（同宽屏，已接）。
- 新会话：推进中行头的 ＋（已接）。iPhone 没有 ⌥⌘N（只在 Mac 菜单里），外接键盘的快捷键表里也没有新会话。
- 搜索会话：搜索页的会话范围不变。
- Cue 页的提示：带会话的提示点了直接打开那个会话页，没有跳会话段的（代码里只剩项目页那一处和调试驱动调 `showSessions`）。

## 要删的旧结构

方案 1：
- `ProgressPane` 与 `Workspace.progressPane`、`AppSettings` 的 `progressPane` 键、`showSessions`；进展页的会话段、`mounted` 与 `shown(_:_:)`；`ProgressPanes`。
- `NewSessionLine`（新会话挪到推进中行头）；宽屏页顶的 `NewSessionButton` 留着。
- 窄屏侧栏那一排的 `ProgressHeader`（分段、额度环与项目范围收在额度面板里那一套），以及 `BarRow` 里中间那块长开、盖住两头的分支。
- 调试：`-CuePadProgressPane`、`-CuePadNarrowCycle` 里换会话段那一步、`InteractionBench+iOS*` 里切段的几处；`SessionNoticeTests`、`SharedPagesTests` 里只为摆场景调的 `showSessions`。
- 文档：docs/layout.md 讲窄屏进展两段的那几句。

方案 2：两层分段（`ProgressPanes`、侧栏的项目｜进展）换成一个三段分段；`BarRow` 长开分支与额度那块同方案 1；`NavigationPane` 与 `progressPane` 要合成一个去处，否则是两份事实源。

## 和 Mac（宽屏）的对应

| | 宽屏现在 | 方案 1 | 方案 2 |
|---|---|---|---|
| 进展 | 只有看板 | 只有看板 | 看板、会话两段 |
| 已结束的会话 | 左栏「更早」 | Cue 页会话条「更早」 | 会话段「历史」 |
| 额度 | 左栏底部，同技能与规则、设置 | 项目段末尾那一组 | 同方案 1 |
| 项目范围 | 看板那一行末尾「⋯」里 | 顶上那一排一颗胶囊 | 同方案 1 |
| 添加任务 | 待办列头 ＋ | 待办行头 ＋ | 同 |
| 新会话 | 文件菜单、⌥⌘N | 推进中行头 ＋ | 会话列表第一行 |

叫法不变；「更早」两端同一个词。新会话放推进中行头是新的，宽屏的推进中列头要不要也放一颗，需要和宽屏一起定。

## 没验证的

- 原型的「更早」页借会话列表的历史读法，排除了绑在置顶任务上的已结束会话；格上的个数却是全部已结束的，两边对不上。落地时页与格读同一个查询（同宽屏 `RailEarlier`）。
- 「更早」页是借 `navigationDestination(isPresented:)` 推的，没有进 `Route`，返回、深链、恢复都没测。
- 推进中行头的 ＋、额度那一行的展开只看了终态，没实点过。
- 会话条很长、要滚的时候「更早」格的位置，没有已结束会话时格不画（代码里是这样，没拍）。
- 深色、辅助字号、读屏、英文（方案 2 三段英文「Projects Board Sessions」在 402 宽可能放不下）、iPhone 横屏都没看。
- 实拍：iPhone 17 浅色，iPad 窄窗 320、375 只拍了进展段顶上那一排。

## 原型怎么起

一次性分支 `proto/head-phone2`，`-CuePadNav one|two` 切方案，不给是现状；`-CuePadNavEarlier YES` 起来推入「更早」页。实现在 `apple/App/Sources/UI/iOS/NavProto.swift` 与几处标了 PROTOTYPE 的分支。效果图：`swift annotate.swift 方案1.json`。

```
apple/scripts/xc.sh shot ios -- -CuePadDemo YES -CuePadNarrow YES -CuePadQuiet YES -CuePadNav one -CuePadScene cue -CuePadNarrowPane progress -CuePadProgressPane board
```
