# 界面文字与英文版

- 唯一事实源是 String Catalog `App/Strings/Localizable.xcstrings`：源语言简体中文，译文英文，跟随系统语言。App、小组件、分享与通知扩展共用这一份；CuePadKit 的界面字也查它（`String(localized:)` 默认查主程序）。键就是代码里的中文原文，由编译器抽取，不手写键；例外只有 CloudKit 通知的 loc-key 与 Info.plist 的键（`InfoPlist.xcstrings`）。工程的开发语言（`DEVELOPMENT_LANGUAGE`）是英文：系统语言既不是中文也不是英文时回落到英文。
- 加字、改字：SwiftUI 的字面量（`Text("…")`、`Button("…")`）自动进目录；自定义视图收界面字的参数用 `LocalizedStringResource`，不用 `String`；模型层、Kit 算出来的界面字用 `String(localized: "…")`。整句带插值写成一个键，不拼碎片：英文语序不同。带数的句子在目录里给英文复数（one / other）。用户写的、Agent 说的内容原样显示（`Text(verbatim:)` 或 `String` 参数）。日期、时间、数字用系统格式化（跟随当前语言），不手写"分钟前""月日"。
- 给 Agent 读的字不进目录：Cue 的系统提示、工具说明与工具结果、技能文件、`cuepad` 命令行、日志，以及只给 Cue 看的报错。它们是调过、评测过的中文，不另出英文版（两份就要两边一起调、一起评测）；Cue 写下的字跟他说话的语言走，他没开口时用界面语言（`CueInterface`）。只在系统提示里说一次不够：照中文句式回的话仍是中文（实测），所以要写的不是中文时，信封每轮在块尾再说一次（`CueEnvelope.Input.language`）。同一句既上界面又给 Cue 看的，界面那份进目录。
- 演示库的内容（Debug 场景里写进库的标题、正文、对话）用 `String(localized: "…", table: "Demo")`，进 `Demo.xcstrings`，只随 Debug 构建：英文截图里出现中文就是漏翻。
- 改完跑 `xc.sh strings`（编两端、收进目录、缺英文的列进 `.derived/strings-todo.json`），用 `strings.py set` 写英文（用法在它的头注释）；`xc.sh check` 查 iOS 构建抽到的字都在目录里、每条都有英文、占位符对得上。
- 英文照 WORDS.md「英文界面」的叫法，地道、简短，Apple 风格（Title Case、"…"表示还要再输入、快捷键写在括号里），不逐字直译；中文里为了说清楚加的字，英文能省就省。英文通常比中文宽一半到一倍：放字的地方不写死宽度，按钮、胶囊、列头在英文下照样不截断不换形，空间实在不够就换更短的说法，不缩字号。验收用英文截图（启动参数 `-AppleLanguages "(en)" -AppleLocale en_US`）。
- 能由字面量构成的类型（`ExpressibleByStringLiteral`）不给 `Text`、`Button`、`Label` 加不带标签的同名初始化器，非加不可就标 `@_disfavoredOverload`：否则 `Text("…")` 选中它，原样显示、不进目录（`Dotted` 踩过）。
