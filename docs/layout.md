# 页面结构与布局

导航、栏、浮层、开合与布局稳定的约定和理由；视觉原则与渲染性能在 [ui.md](ui.md)。

## 导航

- 布局只有窄屏、宽屏，按可用宽度选、不按系统分业务：Mac 是宽屏，iPad 窄窗同手机、宽窗同 Mac。导航只有 `Workspace.navigation` 一份，状态、各入口在两种布局下做什么、尺寸变了怎么转换，都在 `Navigation.swift` 与 `Workspace+Navigation`、`+Narrow`、`+Wide` 的注释里；偏好在 `AppSettings`。
- 窄屏打开就是 Cue，只有以 Cue 为根的一个栈。项目｜进展是根上的满屏侧栏：右滑或与名牌同一排的侧栏钮打开，左滑或点侧栏右上的 Cue 头像回 Cue；推入页盖在两者上，返回是系统的。Cue 页的名牌不随导航挪位置。Cue 页左边常驻会话条，最底下"更早"那一格推入已结束的会话。
- 宽屏是会话条、主区、右边的 Cue。导航只在会话条一处：项目、进展、更早三行（与会话同一种行；更早是已结束的会话，点了在主区打开"更早"那一页，`EarlierPage`，三端同一页），下面等你、推进中。「项目」只表示项目列表，项目页是从列表进去的一页。主区是项目列表或进展（浏览落点）、项目页、一个会话、并排两个会话，或更早、设置、搜索、归档、回收站、技能与规则这类辅助去处；右边一直是 Cue，不进导航。
- 会话条两端是同一个组件（`SessionRail`，分组格与几种宽窄在它的头注释）。Cue 交活的光点落在对应的格子上，Cue 页不另放待回复提示。宽屏会话条收起与展开同一套排法：每一组左沿不动，每一行行首一格在中轴上（Mac 对着中间那颗红绿灯），展开只露出右边的名字、读数与额度，格不挪位（`Chrome` 头注释）。Mac 的开合钮不归会话条：它在最顶那一排、红绿灯右边，两种宽下不动（`SidebarToggle`）。
- 宽屏三栏的尺寸只在 `WideMetrics`（外框各处的数在 `Chrome`）：会话条宽 256，收起是图标条（Mac 98，红绿灯两侧留白相等；iPad 80）；Cue 400；主区最窄只有一个数，并排两个会话的宽 780，不随主区放什么页变。会话条与 Cue 的自动收起只看窗口宽与用户的两个开合选择，换页时栏不动。窗口变窄时只往收里走：先把会话条收成图标条，再把 Cue 收成一颗钮；收 Cue 时不把会话条放回宽版。两个开合都是用户选择，自动收起只改呈现、不改选择：
  - 会话条：开合钮（Mac 在最顶那一排、红绿灯右边；iPad 在会话条顶上）与 ⌃⌘S，只存一份（`AppSettings.railExpanded`）。
  - Cue（`AppSettings.cueOpen`）：Mac 点 Cue 栏头最右的收起右栏、点 Cue 钮放回，两头都是 ⌃⌘I（"显示 › 右栏"，同 SwiftUI 检查器的系统惯例，与 ⌃⌘S 成对）；iPad 的 Cue 钮一直在会话条顶上、开合都点它。

  会话条不能拖宽；并排两个会话均分主区，分隔线不能拖。临界宽：Mac 宽会话条 + Cue 要 ≥ 1436；图标条 + Cue 是 1278–1435；再窄 Cue 收成钮。iPad 图标条 + Cue 要 1260。看板放不下四列最窄时整排横滑，不为它收栏。
- 打开会话：点会话条、看板卡、通知或深链都开在主区（替换主区，此刻并排的右半关掉）；⌘ 点、右键"在旁边打开"或把格子拖到主区右半，开在右半与此刻的会话并排（主区不是会话时同普通打开）。同一个会话只在一边。拖栏头的标题到另一半换边，松手才改去处，途中目标那一半淡铺"放在这里"。Cue 收成钮又放不下时，点 Cue 钮或去 Cue 的入口（深链、通知、对 Cue 说），它从窗口右缘拉出抽屉（`PanelStyle.drawer`），盖在主区上；点抽屉外面关、那一下不落到下面，Esc、换主区也关。抽屉开着时右上不画 Cue 钮。
- 关会话：栏头 ×。关左半时右半的会话占满主区，只开一个时回项目列表或进展。打开会话不改浏览选择，也不另存返回来源。「项目」一行在项目列表与项目页上都是选中，「进展」一行只在看板上，「更早」只在更早页上；别的页与会话不画选中底（`Workspace.shownPane`）。
- ⌃Tab 在主区两半与 Cue 之间换输入焦点，⌘⌥← / → 把有焦点的会话挪向那一边（命令在"显示"菜单）。焦点由控件系统持有（`WideFocus` 读真实的第一响应者），导航里不存焦点副本；发送只取回复框绑定的那个会话，每个会话的草稿按记录 id 存，换边不丢。
- 一个窗口里哪些会话看得见只有 `Workspace.shownSessions` 一份（宽屏是主区开着的，并排时左、右；窄屏只取推入的会话页），同步层再按前后台、遮挡与人在不在处理；界面不自己另算一组。Cue 页的可见性走 `CueViewing`。

## 栏头与页顶

- Mac 窗口工具栏是一条空的，只给最顶那一排定高、把红绿灯放在它中线上（`Chrome.band`）。三栏的栏头都在这一排、同一中线、同一种控件高（`Chrome` 头注释）：这一排整窗是一块连续的底，会话条的底色从它下面才开始：左端是红绿灯与紧挨着的会话条开合钮（无底的图标，悬停才有淡底），两种宽下不动；会话条收起时开合钮伸进主区那一段，主区栏头与看板列头的左边让出它（`Chrome.headLead`），这一排里没有会话条与主区的分界。主区栏头右端是搜索（⌘K，玻璃圆钮）与"⋯"（Mac 的惯例：工具栏右端是这一页的操作与搜索），浏览页、辅助页、看板那一排与会话栏头都一样，并排两个会话时只在左半，一个窗口只一颗。主区看板时四列列头就是这一排（待办列头带 ＋ 添加任务，推进中列头带 ＋ 新会话），"⋯"收着项目范围与归档做完的；项目页是「项目 / 项目名」（点「项目」回项目列表）与介绍；项目列表、更早、归档、回收站写页名，项目列表右边一颗新建项目；技能与规则是规则｜技能与说明；会话是「项目 / 会话名」与 ×（左半的 × 左边是搜索），并排时各一个；右边 Cue 是名牌（`CueTitle`，与手机、iPad 的名牌同一个 `CuePlate`：一块玻璃，头像占两行、右边名字与数字账）与最右一颗收起右栏的图标钮（无底，同这一排别的图标钮），点名牌从它下面长出 Cue 的面板（`CueNowPanel`，三端同一份；Mac 上是气泡，记忆、定时都在里面）。Cue 收起后右上一颗 Cue 钮，压在最右那一块的栏头右端，那一块让出它。这一排是标题栏：主区与 Cue 各是一个嵌着的托管视图，不让标题栏自己拖（不然钮点不进去，`ColumnHostingView`），栏头的空处挂系统的拖窗口手势（`windowDragArea`），按住照样能拖窗口。iPad 宽屏同此结构，主区与 Cue 的页顶仍是页自己画的那一排（下一条）。栏头不放导航（项目｜进展在会话条里），只放 Workspace 里已有的状态，读不到页面读的库就不抄一份（那是第二个事实源）；其余操作在"⋯"。新会话三端只有一个入口：看板推进中列头（手机是推进中那一行行头）的 ＋（`LaneAdd`），另外只有会话列表空着时那一颗；Mac 的 ⌥⌘N 是同一张表单的快捷键。控件按条件写；出没会挤动同一排旁边的（同步提醒、技能与规则的说明）才挂着、只换可见（`keepsPlace`）。
- Mac 的编辑浮层（灵感编辑页、技能与规则的文件页，`Workspace.overlay`）盖在主区上：收起是主区栏头里一颗返回图标的圆钮（`CloseButton`，说"收起"，Esc 同），是哪一份写在它旁边（`OverlayTitle`，内容由页交给 `OverlayHeader`），同手机推入页的系统返回与页顶中间那块，页里不另写。
- 手机与 iPad 的页顶那一排只有一种（`floatingHeader`）：左右各一颗圆钮、中间一两块玻璃，玻璃之间透出内容。窄屏根上的页与宽屏栏里的页自己画这一排，系统导航栏只给推入的页：推入页左边是系统的返回（左缘右滑返回是系统的，所以推入页不藏系统导航栏），推入时根上那一排随页让出，不与推入页的栏项交叉滑动。
- 窄屏侧栏顶上只有一排（`NarrowSidebarBar`）：正中项目｜进展；左边搜索与这一段的低频操作（项目段新建项目，进展段项目范围）；右边额度环与 Cue 头像。换段时只有选中块滑过去、左边第二颗换掉，其余不动；放不下时项目｜进展只画图标。Cue 页的名牌铺满侧栏钮右边那一整行（侧栏钮与名牌同一排）。添加任务在待办那一行行头的 ＋，新会话在推进中那一行行头的 ＋。推入页与宽屏栏里的页照写页名，宽屏项目页的名字写在主区栏头。

## 页面与布局稳定

- 栏头与工具栏的内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 布局要稳定：容器多大只看它是什么，不看里面填了多少——空、少、满同一套尺寸；可选的那一行没有也占着位置，计数原地换数、不让一行出现又消失。内容一变整块就缩、就跳，用户读作出了什么事，眼睛还得重新找。例：竖屏 iPhone 的进展页四行铺满顶栏到底部，行高只由这段高定，空行、卡多卡少都不改（`PhoneBoard`；横屏同 iPad、Mac 四列，`BoardColumns`：四列等分可见宽、一列有最小宽，不按卡多卡少分；放不下时整排横向滚动、最右一列露出一截（放得下时同一个滚动区只是滚不动，拖过最窄宽不换结构），iPad 也一样，不换竖版）；卡标题的行数按列宽给上限、卡高跟着标题实际排了几行走（`BoardCardMetrics`：预留到上限时一行标题下面空一大块，读作没排好）；页顶那一排中间那块玻璃先定高再上玻璃，项目没写介绍也与两侧圆钮同高（`HeaderPiece`）；同样的还有 Mac 项目页顶的介绍行（`ProjectPage`）、置顶项目卡与"更早"行的第二行、会话条的项目与进展两行。列表的条数是内容，行随条数增减；不变的是每一行、每一块自己的尺寸。
- 滚动区内容的边用 `safeAreaPadding`，不用 `contentMargins(…, for: .scrollContent)`：同一棵树里几块滚动区在同一次更新里定内容边距时，SwiftUI 会把一块的边距写到另一块上、之后不改回，安全区的边每次排版重算。滚动条要贴原来的边就用负的 `contentMargins(…, for: .scrollIndicators)` 抵回。唯一例外是清掉系统列表默认顶边的 `contentMargins(.top, 0)`（`RouteView`）：安全区加不出负数。
- 手机输入框里的选择菜单用 `MenuButton`，不用 SwiftUI 的 `Menu`：菜单一开键盘变矮，输入框会掉下去再弹回（理由在它的头注释）。
- 资料库读不出来时一个窗口只有一张"读不出资料库"的卡（`CatalogGate` 只挂在窗口的根上：iOS 的根、Mac 主窗口三栏外面），整窗居中，同启动时打不开库的那一扇；挂在每一栏上时一屏并排两三张一样的卡。
- 读库的修饰符（`observing`）挂在一个真的视图上，读不出来时可以是 `Color.clear`：订阅等视图出现才启动，什么都不排它就不启动，页面永远空白。
- 手机与 iPad 推入页导航栏里的项在推入时就建好、之后只换内容，控件随数据置灰而不出现消失：推入转场期间系统不重建这些项，换项要等转场结束才显示，标题会晚到近一秒。
- 手机与 iPad 上从顶栏长出的面板（Cue 的名牌、额度环）只有 `GrowPanel` 一种：同一块玻璃原地长大，点外面收回，不退成系统弹出框（导航栏里的项画不到栏外，所以有面板的页都是根页、那一排页自己画）。两侧圆钮之间放得下就停在手机那一档宽、居中让出圆钮，放不下就铺满、整颗盖住，不露半颗；窄屏侧栏的额度钮贴右，玻璃从钮往左往下长，钮与 Cue 头像不挪。面板里不放滚动区：会被写上页面滚动区的内容边距（上面滚动区内容的边那条）。Cue 的面板只放 Cue 自己的、会天天变的（列在 `CueNowPanel` 头注释，三端同一份），空、少、满一个尺寸，还没启用时没有刚记下与定时两项；在做的会话从会话条进入；已结束的会话在会话条的更早。Mac 上开合不逐帧长大（下面"Mac 上开合"那条），额度明细是从额度环长出的气泡，Cue 的面板是从 Cue 栏头头像那一块长出的气泡。
- Cue 的现状各处读同一份 `CueNow` 与 `CueBeat`，不按画面各算一次。名牌、菜单栏与小组件显示数字账；灵动岛常驻的信息取舍与展开布局见 `CueActivityViews`，不能把完整数字账塞进状态栏。App 与菜单栏图标的角标只数等你（`CueNow.needsYou`）。
- 开着时才有的透明接点层（点面板外收起、点别处收回）用 `.transition(.identity)`，收起那一下就撤：跟着收起的动画走的话，它淡完之前还接点按，收起后紧接着点下面的东西会点在它上面（Cue 面板就这样被点开回来过）。
- 设置各端同一页、同一套分组与说法，按要紧排：最上面一组是 Cue（不另写组名：第一行就是它——头像、就地改的名字与开关，开关是 Cue 唯一的停用入口，Cue 面板里（三端同一份）是同一个；开着时下面一行是在哪台 Mac 上运行），下面是 iCloud 同步、通知、外观；Mac 设置窗口只有通用与 Agent 两页，Cue 那组在通用页最上面。一项设置只在一处改：用哪个 Agent 与模型只在 Cue 页上。选在哪台 Mac 上运行的菜单各入口同一份（`CueHostMenu`）。
- 沉浸式的栏：页顶那一排与页里钉住的一块（看板列头与手机看板的行头、分段、筛选）都浮在内容上，内容一直滚到它们后面、从玻璃之间和玻璃里透出来。它们后面、下面不加遮罩、渐变、模糊或底色，滚动区也不从它们的下沿开始（那等于把内容裁在下沿）。对话底上浮着的回复框与拍板卡同样：对话滚到它们后面、从圆角四周露出来，后面不铺底色（`FloatingReply`），两端同。窗口最顶那一条：Mac 的工具栏与栏头那一排同样什么都不垫。例外只有宽屏（Mac 与 iPad）的右边 Cue 与会话两栏：栏头是写着字的一排，或是比栏窄、两侧透出内容的名牌（iPad 的 Cue），内容到栏头下沿就淡进栏的底色，不一刀切开、不从名牌两侧露出来（`fadesUnderHead`）；iPhone、iPad 的状态栏那一条是系统的渐进模糊，整个窗口一份，顶上最糊、到状态栏下沿减到不糊，不着色、不垫底，时间与电量才不和滚过去的字叠在一起。用户定的，撤回过两次；规矩在 `Bars`。
- Mac 上不用 NSWindow sheet、`NSAlert`、`runModal`（`lint.sh` 查）：开、关都把主线程关在约 300ms 的嵌套循环里。窗口内的浮层只有 `panel`，确认框是 `dialog`；关法、模态与焦点交还在 `Panel+macOS.swift`。Cue 放不下时的右缘抽屉是它的抽屉样式（`drawer(isPresented:)`，一直挂着，关着滑出窗外），两端同一套。
- 菜单与浮层各一个出处：菜单一律系统菜单（`contextMenu`、`Menu`），每类对象一份内容，出现在哪都用它（会话是 `OpenSessionBeside` + `SessionActions`，任务是 `CardActions`）；挂菜单的那一层不包在定时重画的容器里（随时间变的悬停提示只包卡面）。自绘的浮出（气泡、弹层、抽屉）只走 `panel`，点外面、Esc 由它一处关。
- 气泡（`PanelStyle.bubble`）的来源只有 `BubbleSource` 一份，摆法一份（`BubblePlacement`）：从控件（按钮、圆钮、胶囊）弹出的挂在控件的框上（两端都用 `bubble(isPresented:)`；手机导航栏里的项按读屏标识在窗口里量）；两端的气泡都画在窗口那一层（`panelHost`，Mac 主窗口、手机与 iPad 的场景根各挂一次，手机的 sheet 里另挂一次），不挂在页或控件上；从一行里点开的（任务行、任务行左滑的"更多"）用按下的那一点、按行高让开整行，行成百上千，不给每行挂几何读数。都没有时在窗口上方居中。手机（窄屏）的任务气泡不对着来源，是贴在底部的纸（`bottom`）。
- 看一条任务只有任务气泡（`TaskBubble`）；点任务行与看板卡时，开工了的叶子直接进它的会话、其余开气泡（`Workspace.enter`）：开工后要看的是会话里的进展。Mac 上也不用系统 popover：它是另一扇窗，进程里第一次弹要 85～113ms，关时主窗口重新变回前台窗口，开着时主窗口的快捷键不响应；窗口内的气泡开约 30ms、关 5～7ms（实测）。
- Mac 上开合不逐帧挪位置：位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，会掉帧十几次。会话条换宽、Cue 收起与放回（开合、窗口跨过临界宽度）时主区几块在这一下就换到终点的位置与宽、页按新的宽排一次，看得见的滑动是渲染端叠加在图层上的平移与右缘收放，相邻几块每一帧都对齐、不重叠不留缝，动画里主线程没有活（`WideColumnView.move`、`SidebarSlide`；SwiftUI 的偏移与几何效果同样每帧重排，不用）。编辑页原地淡入淡出；有字的一块进出场不缩放（理由在 `Bubble.swift`）。
