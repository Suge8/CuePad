# 页面结构与布局

导航、栏、浮层、开合与布局稳定的约定和理由；视觉原则与渲染性能在 [ui.md](ui.md)。

## 导航

- 布局只有窄屏、宽屏，按可用宽度选、不按系统分业务：Mac 是宽屏，iPad 窄窗同手机、宽窗同 Mac。导航只有 `Workspace.navigation` 一份，状态、各入口在两种布局下做什么、尺寸变了怎么转换，都在 `Navigation.swift` 与 `Workspace+Navigation`、`+Narrow`、`+Wide` 的注释里；偏好在 `AppSettings`。
- 窄屏打开就是 Cue，只有以 Cue 为根的一个栈。项目｜进展是根上的满屏侧栏：右滑或 Cue 页左上的侧栏钮打开，左滑或点侧栏右上的 Cue 头像回 Cue；推入页盖在两者上，返回是系统的。Cue 页的名牌不随导航挪位置。
- 宽屏是会话条、主区、右栏。主区是项目｜进展的浏览落点、一个会话，或设置、搜索、归档、回收站、技能与规则这类辅助去处；右栏是 Cue 或一个会话，Cue 只有右栏这一份。
- 会话条两端是同一个组件（`SessionRail`，分组格与几种宽窄在它的头注释）。Cue 交活的光点落在对应的格子上，Cue 页不另放待回复提示。
- 宽屏会话条的开合只有一个用户选择（`AppSettings.railExpanded`，侧栏钮与 ⌃⌘S 同一个入口）。窗口放不下宽条时自动收窄，只改呈现、不改这个选择；临界宽度按宽条加两栏的最窄宽推出（`WideMetrics.threshold`）。两个会话均分余宽，分隔线不能拖。
- 打开会话：点会话条、看板卡、通知或深链默认开在右栏；⌘ 点、右键"在左边打开"或把格子拖到左栏，开在左栏。同一个会话只在一栏：开到另一栏是搬过去、替换那一栏，不复制。拖栏头的标题换边，松手才改去处，途中目标栏淡铺"放在这里"；两栏都是会话时交换。
- 关栏：左栏 × 回项目｜进展的浏览落点（之前打开的项目还是那个），右栏 × 回 Cue。打开会话不改浏览选择，也不另存返回来源；主区不是浏览页时项目｜进展不画选中底。
- ⌃Tab 在两栏间换输入焦点，⌘⌥← / → 把有焦点那栏的会话挪向那一边（命令在"显示"菜单）。焦点由控件系统持有（`WideFocus` 读真实的第一响应者），导航里不存焦点副本；发送只取回复框绑定的那个会话，每个会话的草稿按记录 id 存，换边不丢。
- 一个窗口里哪些会话看得见只有 `Workspace.shownSessions` 一份（左、右，不重复；窄屏只取推入的会话页），同步层再按前后台、遮挡与人在不在处理；界面不自己另算一组。Cue 页的可见性走 `CueViewing`。

## 栏头与页顶

- Mac 窗口工具栏只放侧栏钮。页面的控件在所属那一栏顶上那一排（与工具栏同一行、同高）：主栏是项目｜进展、开着编辑浮层时的收起与标题、搜索与"⋯"；右栏的 Cue 是页头（`CueTitle`）与记忆、定时两颗圆钮；会话栏是标题与 ×（`WideSessionTitle`）。进展页的看板｜会话、项目范围与新会话在页自己顶上那一排，看板列头在各自那一列的顶上。栏头只放 Workspace 里已有的状态，读不到页面读的库就不抄一份（那是第二个事实源）；状态归页面的（会话段的搜索框）留在页里，其余操作在"⋯"。只属于一页的控件随那一页第一次出现才建，之后一直挂着、只换内容与可见（`PageControl`、`toolbarPresence`）。
- Mac 的编辑浮层（灵感编辑页、技能与规则的文件页，`Workspace.overlay`）盖在主区上：收起是主栏栏头里一颗返回图标的圆钮（`CloseButton`，说"收起"，Esc 同），是哪一份写在它旁边（`OverlayTitle`，内容由页交给 `OverlayHeader`），同手机推入页的系统返回与页顶中间那块，页里不另写。
- 手机与 iPad 的页顶那一排只有一种（`floatingHeader`）：左右各一颗圆钮、中间一两块玻璃，玻璃之间透出内容。窄屏根上的页（Cue 页、侧栏的项目与进展两段）与宽屏栏里的页自己画这一排，系统导航栏只给推入的页：推入页左边是系统的返回（左缘右滑返回是系统的，所以推入页不藏系统导航栏），推入时根上那一排随页让出，不与推入页的栏项交叉滑动。
- 页顶不写页名大标题：窄屏侧栏顶上的项目｜进展已经说了在哪一页（`HeaderHost.namesPage`）；推入页与宽屏栏里的页照写。根页中间只放这一页看什么：Cue 页是 Cue 的名牌（定宽定高，`CueHeader`）；进展段是看板｜会话、项目范围（两段共用 `Workspace.projectScope`）与额度环并成的一块，左边搜索钮；项目段是一条搜索框，放大镜正落在进展段搜索钮的位置，换段时不跳（`HeaderSearch`）。右边只放这一页自己的操作。

## 页面与布局稳定

- 栏头与工具栏的内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 布局要稳定：容器多大只看它是什么，不看里面填了多少——空、少、满同一套尺寸；可选的那一行没有也占着位置，计数原地换数、不让一行出现又消失。内容一变整块就缩、就跳，用户读作出了什么事，眼睛还得重新找。例：竖屏 iPhone 的进展页四行铺满顶栏到底部，行高只由这段高定，空行、卡多卡少都不改（`PhoneBoard`；横屏同 iPad、Mac 四列：列最窄 160，放不下四列时横向滚动、最右一列露出一截，`BoardColumns`）；卡留足标题行数、同一列的卡等高（`BoardCardMetrics`）；页顶那一排中间那块玻璃先定高再上玻璃，项目没写介绍也与两侧圆钮同高（`HeaderPiece`）；同样的还有 Mac 项目页顶的介绍行（`ProjectPage`）、置顶项目卡与"更早"行的第二行、会话条的 Cue 头像与名字。列表的条数是内容，行随条数增减；不变的是每一行、每一块自己的尺寸。
- 滚动区内容的边用 `safeAreaPadding`，不用 `contentMargins(…, for: .scrollContent)`：同一棵树里几块滚动区在同一次更新里定内容边距时，SwiftUI 会把一块的边距写到另一块上、之后不改回，安全区的边每次排版重算。滚动条要贴原来的边就用负的 `contentMargins(…, for: .scrollIndicators)` 抵回。唯一例外是清掉系统列表默认顶边的 `contentMargins(.top, 0)`（`RouteView`）：安全区加不出负数。
- 手机输入框里的选择菜单用 `MenuButton`，不用 SwiftUI 的 `Menu`：菜单一开键盘变矮，输入框会掉下去再弹回（理由在它的头注释）。
- 读库的修饰符（`observing`）挂在一个真的视图上，读不出来时可以是 `Color.clear`：订阅等视图出现才启动，什么都不排它就不启动，页面永远空白。
- 手机与 iPad 推入页导航栏里的项在推入时就建好、之后只换内容，控件随数据置灰而不出现消失：推入转场期间系统不重建这些项，换项要等转场结束才显示，标题会晚到近一秒。
- 手机与 iPad 上从顶栏长出的面板（Cue 的名牌、进展页的额度环）只有 `GrowPanel` 一种：同一块玻璃原地长大，点外面收回，不退成系统弹出框（导航栏里的项画不到栏外，所以有面板的页都是根页、那一排页自己画）。两侧圆钮之间放得下就停在手机那一档宽、居中让出圆钮，放不下就铺满、整颗盖住，不露半颗。面板里不放滚动区：会被写上页面滚动区的内容边距（上面滚动区内容的边那条）。Cue 的面板只放 Cue 自己的、会天天变的（列在 `CueNowPanel` 头注释），空、少、满与启用前后一个尺寸；在做的会话从会话条进入；全部会话与历史仍在进展页的会话段。Mac 上开合不逐帧长大（下面"Mac 上开合"那条），额度明细是从额度环长出的气泡。
- Cue 的现状各处读同一份 `CueNow` 与 `CueBeat`，不按画面各算一次。名牌、菜单栏与小组件显示数字账；灵动岛常驻的信息取舍与展开布局见 `CueActivityViews`，不能把完整数字账塞进状态栏。App 与菜单栏图标的角标只数等你（`CueNow.needsYou`）。
- 开着时才有的透明接点层（点面板外收起、点别处收回）用 `.transition(.identity)`，收起那一下就撤：跟着收起的动画走的话，它淡完之前还接点按，收起后紧接着点下面的东西会点在它上面（Cue 面板就这样被点开回来过）。
- 设置各端同一页、同一套分组与说法，按要紧排：最上面一组是 Cue（组名是它的名字，只有名字与在哪台 Mac 上运行两行），下面是 iCloud 同步、通知、外观；Mac 设置窗口只有通用与 Agent 两页，Cue 那组在通用页最上面。一项设置只在一处改：用哪个 Agent 与模型只在 Cue 页上。选在哪台 Mac 上运行的菜单各入口同一份（`CueHostMenu`）。
- 沉浸式的栏：页顶那一排与页里钉住的一块（看板列头与手机看板的行头、分段、筛选）都浮在内容上，内容一直滚到它们后面、从玻璃之间和玻璃里透出来。它们后面、下面不加遮罩、渐变、模糊或底色，滚动区也不从它们的下沿开始（那等于把内容裁在下沿）。窗口最顶那一条：Mac 的工具栏与栏头那一排同样什么都不垫；iPhone、iPad 的状态栏那一条是系统的渐进模糊，整个窗口一份，顶上最糊、到状态栏下沿减到不糊，不着色、不垫底，时间与电量才不和滚过去的字叠在一起。用户定的，撤回过两次；规矩在 `Bars`。
- Mac 上不用 NSWindow sheet、`NSAlert`、`runModal`（`lint.sh` 查）：开、关都把主线程关在约 300ms 的嵌套循环里。窗口内的浮层只有 `panel`，确认框是 `dialog`；关法、模态与焦点交还在 `Panel+macOS.swift`。
- 气泡（`PanelStyle.bubble`）的来源只有 `BubbleSource` 一份，摆法一份（`BubblePlacement`）：从控件（按钮、圆钮、胶囊）弹出的挂在控件的框上（Mac 用 `bubble(isPresented:)`；手机栏里的圆钮点下按读屏标识量 `ControlAnchor`）；从一行里点开的（任务行、任务行左滑的"更多"）用按下的那一点、按行高让开整行，行成百上千，不给每行挂几何读数。都没有时在窗口上方居中。手机（窄屏）的任务气泡不对着来源，是贴在底部的纸（`bottom`）。
- 看一条任务只有任务气泡（`TaskBubble`）；点任务行与看板卡时，开工了的叶子直接进它的会话、其余开气泡（`Workspace.enter`）：开工后要看的是会话里的进展。Mac 上也不用系统 popover：它是另一扇窗，进程里第一次弹要 85～113ms，关时主窗口重新变回前台窗口，开着时主窗口的快捷键不响应；窗口内的气泡开约 30ms、关 5～7ms（实测）。
- Mac 上开合不逐帧挪位置：位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，会掉帧十几次。会话条换宽（开合、窗口跨过临界宽度）时两栏在这一下就换到终点的位置与宽、页按新的宽排一次，看得见的滑动是渲染端叠加在图层上的平移与右缘收放，两栏每一帧都对齐、不重叠不留缝，动画里主线程没有活（`WideColumnView.move`、`SidebarSlide`；SwiftUI 的偏移与几何效果同样每帧重排，不用）。编辑页原地淡入淡出；有字的一块进出场不缩放（理由在 `Bubble.swift`）。
