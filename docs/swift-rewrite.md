# CuePad Swift 重写方案

CuePad 从 Electron + Svelte + Rust sidecar 整体重写为 Swift 原生应用：macOS 26+、iOS/iPadOS 26+，iCloud 同步，Pi 深度集成。Windows 与 Android 不做。本文是重写期间的事实源；Swift 版落地后改写为 `docs/development.md`，本文件删除。

## 产品

CuePad 是开发者与编程 agent 协作时的思考空间：写 prompt、记想法与目标、看 agent 在做什么、把内容一键交给 agent。功能只服务一条循环：**捕获 → 打磨 → 发出 → 回看**。卡片承载思考（任意长，可含图片、分块和作为正文一部分的清单文字），任务承载要去做的一句话。

| 概念 | 定义 |
| --- | --- |
| 项目 | 卡片的分组；可绑定一个代码目录，Pi 会话按工作目录自动归入 |
| 卡片 | 唯一的内容类型：文字 + 内联图片 + `{{变量}}` + 分块。prompt、思考、目标、笔记都是卡片 |
| 任务 | 独立记录的一行待办，默认全局、可挂到项目；可选一键发给 Pi 会话并显示其状态，完成由用户勾选；可与卡片互转（移动而非复制）。不做子任务、截止日期、优先级、提醒 |
| 活动 | Pi 会话的历史索引 + 实时状态，只读，不复制会话原文 |
| 发送记录 | 每次投送/复制自动记录内容快照、目标与时间，可一键重发；即自动日志 |

投送目标有两类：**Pi 会话**（经扩展通道直达，支持图文，无需辅助功能权限）与**任意应用**（剪贴板 + 定向 `Cmd+V`，仅文字）。

## 架构

一个 Xcode 工程：macOS App 与 iOS/iPadOS App，共用本地 Swift 包。Swift 6 严格并发，界面 SwiftUI，编辑器与菜单栏唤起面板用 AppKit/UIKit。

| 模块 | 职责 | 平台 |
| --- | --- | --- |
| Store | 系统 SQLite3 直连（零第三方依赖）的唯一事实源；写事务提交后发布变更，界面据此重读查询，不在内存复制状态；FTS5 搜索 | 全部 |
| Sync | 直接用 CKSyncEngine 同步 Store 的记录；图片以 CKAsset 同步；正文用加密字段 | 全部 |
| Editor | TextKit 2 编辑器：内联图片、分块、变量高亮；文本模型共用，AppKit/UIKit 各一层宿主 | 全部 |
| Dispatch | 权限预检 → 写剪贴板 → 激活目标 → 定向 `Cmd+V`，单一串行队列 | macOS |
| Agent | FSEvents 索引 Pi 会话文件（历史）；Unix socket 连接 Pi 扩展（实时状态与图文发送） | macOS |

- **数据**：ID 用 UUID；排序用分数索引字符串，避免多设备排序冲突；软删除只保留 `deletedAt`，项目删除时其卡片随项目进回收站（由项目推导，不逐卡记录来源）。设备本地偏好（主题、快捷键、自动发送、当前项目）进 UserDefaults，不进同步库。变量上次取值存在卡片上并同步。
- **图片**：按内容哈希存文件去重，正文存附件引用；缩略图为派生缓存，不同步。
- **冲突**：iCloud 按记录同步。同一卡片离线并发编辑时保留两个版本交给用户选择，不静默覆盖。任务是独立记录而非卡片正文里的清单，勾选只改该条，不与卡片编辑冲突。
- **编辑器**：存储格式是纯字符串，唯一事实源——分块为独占行 `---split---`，图片为行内 `![](cuepad://img/<哈希>)`；运行时二者各为 U+FFFC + 附件，保存只经序列化，编辑器内复制输出存储格式。解析/序列化/分块编辑/光标规范化放在仅依赖 Foundation 的共用模型里。变量高亮用 `NSTextLayoutManager` 渲染属性（不写 storage、不进 undo），监听 `didProcessEditingNotification` 以覆盖输入法组合期。禁止访问 `NSTextView.layoutManager`（会永久降级到 TextKit 1）。附件只挂降采样缩略图并按视口懒加载，原图留在文件。iOS 另写粘贴/拖入委托、光标规范化（改写 `selectedTextRange`）与工具栏"分块"按钮。
- **Pi 桥**：扩展随 App 打包，首次启动征得同意后写入 Pi 扩展目录；要求 Pi ≥ 0.84.4（有 `ui_prompt_*` 事件）。每个会话在短路径目录（`sun_path` 上限 104 字节，不用 `$TMPDIR`）开 `<sessionId>.<pid>.sock`，目录 0700、socket 0600，两端都校验属主与权限。协议为 JSON 行（v1，模块 README 为准）：扩展只在 tui/rpc 模式开 socket；连接后先收 `hello` 快照（协议版本、扩展版本、pid、cwd、会话文件、终端），再收状态切换：思考中/输出中/工具（名称）/等待用户/完成/出错；只有 `agent_settled` 是完成，`/new` 先 `bye` 再开新 socket。"等待用户"只覆盖扩展发起的弹窗，Pi 无内置工具审批。客户端启动与目录事件时全量重扫，不依赖创建事件；断开即会话结束，残留 socket 由 kqueue 进程退出通知触发删除（强杀后 EOF 到达时进程可能仍是僵尸，不能用 `kill(pid,0)` 判死）。同一会话允许多客户端，各自收快照与全部状态，`ack` 只回发送方。实时状态只在内存，历史只来自 Pi 会话文件：沿当前分支解析、只读新增字节、偏移存进 Store，首次索引后台进行、按修改时间倒序。
- **发给 Pi**："直接发送"支持文字 + 图片与 steer/followUp；"放进输入框"只有文字，用 `pasteToEditor`（`setEditorText` 会覆盖用户已输入内容），含图片的卡片只能直接发送。图片发原图，Pi 自行缩放（最长边 2000px、base64 ≤ 4.5MB）。
- **投送**：进程内 `Dispatcher` actor，经前台应用/剪贴板/按键三个协议接缝测试。顺序靠任务链而非 actor 本身（actor 在 await 处可重入）。激活先订阅通知再调用，超时报错不发键。激活用 `NSRunningApplication.activate()`（人工冒烟：从其他前台应用激活目标并粘贴成功，连续投送不丢不乱，目标未运行时报错且不动剪贴板）。单条目同时放文字与 PNG 时，图形应用只取其一（TextEdit 取了图片），图文需写成按原顺序含图的 RTFD 并附纯文字兜底，阶段 1 验证。辅助功能授权归属 CuePad.app。窗口隐藏与发送记录由调用方负责。
- **分发**：macOS 用 Developer ID 签名 + 公证，官网分发，Sparkle 更新（辅助功能权限使其不能进 Mac App Store）；iOS/iPadOS 走 TestFlight/App Store。签名与公证用 App Store Connect API 密钥，全程命令行。
- **测试**：Swift Testing 覆盖 Store、同步映射、Pi 会话解析与桥协议、投送队列；XCUITest 只保留关键流程冒烟；另建"构建 → 运行 → 截图"的视觉验收流程。

## 视觉

内容是纸，控件是玻璃：编辑器与卡片用安静的实色底并保留纸感品牌；工具栏、侧栏、弹层、菜单栏面板用系统 Liquid Glass 组件，玻璃不叠玻璃；"降低透明度""增强对比度"开启时自动退回实底。

Mac 版采用"近处卡片、远处列表"（设计原型方向 D，spike/swift-phase0 分支 spikes/design）：

- **导航**：可收起的玻璃侧栏（⌘\），分置顶 / 最近项目 / 全局 Pi 会话；⌘1–9 切项目。
- **项目页三段**：顶部"目标与下一步"（项目目标卡 + 该项目未完成任务 + 该项目的 Pi），下滚时收成一行，无目标则不显示目标栏；中间工作集卡片墙（置顶单列，其余为最近编辑或未发送，只在打开项目或跨天时重排）；下方"更早"按周分组的紧凑列表，3 个月以上按月折叠，再次编辑的卡回到墙上。
- **全局**：⌘K 搜索（跨项目，按项目/含图片/发送目标/时间筛选，结果带预览）；右上角面板专放全部任务；底部玻璃输入栏随手记存卡或直接发给 Pi，正文底部渐隐，玻璃下不叠字。
- **编辑**：卡片连续放大成居中的纸页，底部玻璃操作栏（复制、分块、变量取值、发送）。菜单栏面板是一张小稿纸，⌘↩ 直接发出。
- **字体**：中文正文一律苹方。
