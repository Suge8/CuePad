# 界面约定

做新界面或视觉改动时，先出原型或截图给用户看，再出文字方案。

## 视觉原则

- 内容是纸，控件是玻璃：灵感与任务的卡片是纸色实底；栏头与页顶的控件、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。用户靠这个一眼分清内容和操作。
- 每多一档颜色，就多一样要用户分辨的东西；石绿不再给第三种事。
- 选中不用靛青：选中说的是"这里放着它"，不是"这里有动静"，全 App 只有一种中性淡底（`Palette.selection`，比悬停深一档）加墨字（字半粗），靛青铺成一块底会压过真正在跑的那几条线。
- 项目色只上图形，不写成字、不做成圆点：圆点和彩字会被读成状态。
- 图标默认不套装饰圆底：分组标题与项目标直接给字形着色；等你用裸问号，实心圆徽只强调失败。任务待办是空圈、进行中是静止开口弧（不表示百分比），有子任务时分段环才表达真实完成比例，原生圆钮表达操作容器，两者不属于图标装饰，不一并去掉；圆钮内部不重复套装饰圆。
- 同一状态处处同一个样子，用户只学一次：新界面引用现成的状态图形，不另画。对勾只表示完成与记下。
- 会话条只用一套分组，不提供旧样式切换。
- logo 就是 Cue 本人：App 图标、菜单栏、图标族、落地页同一个形象。
- 灵动岛是例外的小视口。扩展只在内容更新时过渡，不移植 App 的循环头像，也不为动画发推送；系统将动画限制在两秒内，Always-On 低亮度时不播（[Apple](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities)）。
- 系统菜单里的标志要显式标为可见：macOS 27、iPadOS 27 起默认藏起菜单项图片。
- 切页只有一种（`Motion.turn`）：分段里靠右的、往里翻的从右边进，靠左的、返回的从左边进，只滑一小段并淡入。
- Mac 照原生控件：单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。和系统应用不一样的地方，用户会觉得是坏了。
- 悬停：悬停时要换颜色、露记号的按钮读 `buttonHovered`，不各自挂 `onHover`；系统控件的悬停与焦点环交给系统。
- 列表行之间不画分割线，靠间距与纸分组（系统 `Form` 与菜单除外）。
- 悬停、选中时才出现的东西不改动周围的排版：随选中变的只换颜色与字重、不插不撤占位置的东西。露出一个钮挤动了标题与时间、选中一格让整条会话条上下跳，都是用户能一眼看见的抖。
- 大字号下空输入框按完整提示排高，气泡是否折叠由实际排版判断，展开入口不覆盖正文。
- 少写字：不写说明句与次级标签，要解释的放问号气泡。

## 渲染性能约束

- 滚动时每帧都变的读数（偏移）不进状态，只放会让状态改变的越线；行里不放 `GeometryReader`。每个几何读数都是一次布局回调，挂在每行上滚动就跟不上。
- 行数不封顶的列表用懒加载栈，懒加载栈里一组行的容器也要懒加载：普通栈打开时把所有行量一遍。例外各在其类型里说明（会话条的分组、会话对话）。
- 输入框每敲一个字的开销不随草稿长度增长：不拿整串比较、不重设整篇的属性，草稿的读者（预览、是否命令）只看开头。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图。
- 第一次打开页面的那一帧只建看得见的：`ViewThatFits` 会把挑剩的候选也建出来，能按尺寸定的用 `Layout` 一次排；`Canvas` 第一次画一张就要几毫秒，几道线、一个环用 `Shape`；打开后紧接着的重活等这一帧画上屏（`NextFrame.drawn`）。
- 先排后动：会动的过渡里，重活（建页、建编辑器、让编辑器接过键盘）放在动之前、每帧一步，动起来之后每帧只剩动画与改透明度。
- 逐行、逐格跑的代码不用正则字面量：每求值一次就新建一份、第一次匹配时再编译（拆 Markdown 曾每行编译三遍）。
