# 界面约定

跨界面的原则与它们的理由；具体界面的规格在各视图文件的头注释里，颜色令牌在 `App/AppGroup/Palette.swift`，字号、间距、动效与表面在 `UI/Shared/Theme/`。能写成检查的规则在 `apple/scripts/lint.sh`，原因写在它的报错里。

做新界面或视觉改动时，先读 ui-craft 与 ui-picks 两个 skill，先出原型或截图给用户看，再出文字方案：界面好不好要看到才判断得了。

## 视觉原则

- 内容是纸，控件是玻璃：灵感与任务的卡片是纸色实底；工具栏、侧栏、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。纸感是品牌，玻璃是系统控件的语言，两者分开用户才一眼分清内容和操作。
- 颜色只有一份，在色板 `Palette`（AppGroup，App、小组件、分享扩展共用）：界面只取令牌，不写色值、不给颜色叠透明度、不用系统灰与系统色（`lint.sh` 查）。新颜色先进色板、定语义名与浅深两档。每多一档颜色，就多一样要用户分辨的东西。
- 底子是纸与墨（logo 与吉祥物的两种颜色），侧栏 < 桌面 < 纸同一色温由深到浅，深色是"夜里的纸"；小组件与分享扩展也是桌面色的底、墨色的字。文字、图标与系统控件的 tint 是墨，墨分三档：正文 `ink`、次要字 `ink2`、只扫一眼的时间计数占位字 `ink3`，三档都是要读的字，在各层底与实底玻璃上都 ≥ 4.5:1。链接是墨色加下划线，不另上色。
- 签名色靛青（`signature`）只给焦点与正在发生的事，一屏通常一两处：主按钮与发送钮、选中项的浅底（`selection`，含侧栏选中的那一行、选中的筛选胶囊）、焦点环、Agent 在跑（工作中、话在路上、接力的飞光、Cue 那一行在管前的流光）、图标点睛点亮。不做装饰、不做链接。在跑与选中都是"这里有动静"，靠形状分：在跑是会动的线，选中是一块底。
- 状态色三种各管一件事：等你确认与待回复赭黄（`waiting`，与"等你 N"同一条规则）、出错与没能送达胭脂（`failure`）、有新回复与 Cue 的新消息石绿（`replied`，Cue 页对话里还没读的话旁的小点 `CueUnreadDot` 也是），停着的是灰；只上状态图形与紧挨着它的那个词，不给整段字上色。Agent 页的会话卡片只给出错与没能送达、有新回复换成淡底（`failureWash`、`repliedWash`，经 `PiShown.wash`）：淡底是这种色相的浅调，不拿字色叠透明（深色的字色叠薄了是灰米、灰粉）；等你确认与待回复不铺大块赭黄（压眼），只上图标与状态字；在跑的不铺，会动的线已经够醒目。赭黄不借给别的用途（"等你"的几件现成样子只在 `Waiting.swift`）；任务的进行中不上色，靠形状。实底（主按钮、删除钮）深色下压到中等明度配暖白字（`onFill`），不用白字配亮色底。
- 其余彩色只表示项目，项目色只上图形（项目图标、任务行末的项目小图标、书架卡的淡底），不写成字、不做成圆点：圆点和彩字会被读成状态。库里存的 8 个值不动，显示时按深浅各取一档（`Palette.project`）。彩色一多，用户就不知道该看哪。
- 状态图形全 App 只有一份：任务只按 `TaskGlyph` 着色，任务圈只有 `TaskRingView`（点它完成只经 `TaskCheckButton`：先显示对勾、停一下再移走，可反悔），任务的行只有 `TaskLine`（手机与 Mac 的项目页同一种，一行只说一遍状态：进行中是圈的半填、会话在做什么是它的状态标），任务页看板上的卡只有 `BoardTaskCard`，行与卡上"下一步"那一格只有 `TaskNextMark`（Mac 与手机同一个判断 `Workspace.next(for:)`）；会话状态的图标与颜色只在 `PiShown.icon`、`tint` 一处定（每种状态的样子与理由在它的注释里）：列表与行首的状态标是 `PiStateDot`，跟着字号的静止图形是 `PiStateGlyph`（问题卡、出错与没能结束的提示、Cue 的等你、iPhone 前台横幅、没能送达的标记），不另取图标。两种意思与会话无关、各有一个公共出处，会话状态与别处都引用它：等你是赭黄问号圆（`Icon.waiting`，赭黄的几件样子在 `Waiting`），出错是胭脂圆叹号（`Icon.failure`、`FailureMark`：会话出错、操作失败的提示、同步出错、启动问题、读不出资料库、崩溃报告都是它，不用三角）。对勾只表示完成与记下。同一状态处处同一个样子，用户只学一次。
- Cue 那一行（Mac 侧栏的 Cue 名片、iPad 侧栏最上面、手机与 iPad 的 Cue 页头、菜单栏面板与输入条）是头像、名字，下面"在管 N · 等你 M"（`TallyLabel`，小组件与实时活动同一个样子，数只读 `CueStore.cueTally`）：在管前是一截靛青流光，Cue 在做事时一道光沿它走、静着不动；等你是赭黄问号与赭黄字；为 0 的那半不写，都为 0 时 Cue 在做事写状态词、静着写一句安静的现状；没启用、起不来、值班的 Mac 不在线写原因；新消息数在行尾（名片上在名字右边）石绿。这一行不写 Cue 最近说的一句：只给扫一眼的现状；那一句只在名片的气泡里。
- 图标只有一个入口 `Icon`（`Theme/Icon.swift`）：全部是自家的墨块符号 `cue.*`（由 `design/tools/cue-symbols.py` 生成），不用系统符号；按意思取名，哪个意思画成哪个符号只在它的映射里写，别处不写符号名（`lint.sh` 查）。意思是"发出"的（发送钮、发送回答、交给）都是同一架纸飞机，只表示方向的（在上面、更早的、回到最新、压缩上下文、自动检查更新）是燕尾箭，两族不互借。项目图标是闭合表 `ProjectIcon`（24 种，Mac 表单三行排满）：表单只给表里的，库里存的就是表里的名字，不迁移、不映射，表外的认不出、是文件夹；Mac 菜单栏是同 logo 的 `Icon.menuBar`（单色模板图）。墨块符号的第二层是点睛，只能是小部件（一处点、一条缝里的块，生成器查占比），主体在主层：点睛平时是前景色的次一级（墨色前景就是次墨），选中或正在发生时靛青、状态图标的点在那个状态存在时上状态色（`IconImage`），单色场合（系统菜单、工具栏）照系统。图标的动效只在事件那一拍放一次（被叫醒、做完的软糖形变 `Jelly`，表情在压得最扁时换），常驻的只走 `LoopLayer`，减弱动态效果时只淡入淡出。
- 品牌标志全 App 只有一份 `BrandMark`（LobeHub 单色标志转的自定义符号，墨色、不用品牌色），标志是产品的、不是公司的：模型显示它的家族（Claude、GPT、Gemini、Grok…，从模型 id 认，转发的模型也认得）；提供方（模型菜单的分组、订阅额度的账号）显示它的产品（Anthropic 是 Claude）；Agent 显示它自己；认不出的（自定义提供方的模型）不带标志，不用通用图标顶替：说不出是哪一家，还会被读成别的意思（芯片曾被当成"默认模型"）。系统菜单里的标志要显式标为可见（macOS 27、iPadOS 27 起默认藏起菜单项图片）。
- 对话里只有说的话是一块：对话气泡只在 Cue 页（两边对说：你的话是牛皮纸色的气泡、Cue 的话是纸做的气泡，`CueBubble`），与 Mac 侧栏名片里 Cue 最近那一句（纸色、尖角指向头像，Cue 页开着时收起）；会话页是 Agent 干活的记录，你的话是一颗四角同圆的牛皮纸块、回答全宽（`BubbleLook.session`），不套 Cue 的气泡样子；Cue 自己醒来的连着几轮是一颗只描虚线、不铺底的气泡（`CueNoteBubble`，色板 `noteEdge`）：是它说的话，但没推给你，每轮写为什么醒、点了去叫醒它的会话；其余都不铺底、不描边——属于一边的是旁注（一轮的经过、此刻在做什么，`NoteLine`），不属于哪一边的是居中的标记（时间、上下文换了、更早的，`ChatMarker`）；你的话到哪了是气泡左下角外的一个小记号（路上只转圈、唤醒已结束的会话才带字，已送达纸飞机，没能送达胭脂叹号、点开是原因全文与重发、移除，`BubbleTrip`），不占一行，只有没能送达在下面多一行"未送达 · 重发"。块只留给说的话与要你操作的卡片（等你、启用），一眼分得出哪句是对你说的。
- 写着要读的字的玻璃（顶栏标题、输入框与回复框、提示横幅）一律 `GlassInk.solid`：内容一直滚到它们后面，背后可能是亮图也可能是深色代码块，只着色的话玻璃被背后衬亮衬暗，字读不出来、叠成一团；垫了九成实的页面底色，字对玻璃在任何背景上都够 4.5:1。只有图标与短标签的圆钮用 `clear`。"降低透明度""增强对比度"开启时退回实底。
- 动效：位移与尺寸用无回弹弹簧，不超过 300ms（`Motion`），动效是告诉用户东西去了哪，不是表演；唯一的例外是 Cue 与会话之间接力的那一下（叫醒与交给，`CueRelayStage`，时长与理由在它那里）；按钮按压的样子只在 `PressFeedback` 定（列表行的底在 `RowStyle`，见下一条），手机缩放回弹加轻触感，Mac 照原生控件按下即变淡、不缩放不震动，因为 Mac 用户拿系统控件作参照；减弱动态效果时位移、尺寸、旋转直接到终态（`Motion.spatial`），确要交代变化的地方换身份整块交叉淡入淡出（`Motion.crossfade`）。
- 列表里一行的选中、按下与悬停底只有一份（`RowStyle`）：形状与所在容器同心（`ConcentricRectangle`，容器用 `rowContainer` 声明）——面板、侧栏里的行浮着、底向两边让出一截，分组纸里的行铺满（同系统分组列表）；调用处只说"这是一行"，不自己画底、圆角与负边距。行容器里铺方的底色要写 `.rect`：不写形状的底色按容器取同心圆角。
- Mac 指针与悬停照访达、邮件：按钮、行与卡片都是箭头，手形只给打开链接的字；系统控件的悬停与焦点环交给系统，自绘的只在悬停才露出东西的地方给反馈，悬停不挪位置；单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。和系统应用不一样的地方，用户会觉得是坏了。
- 字体：中文正文一律苹方。字号、行距与 Mac 页面间距只在 `Typography`、`Spacing` 按角色定义，改一处全 App 跟着变；Mac 没有动态字体且系统样式偏小，按角色给固定字号、比系统高一档。
- 空态与出错页是吉祥物加一句现状（`EmptyState`）：吉祥物是品牌 IP，空页是它出场最多的地方，全 App 统一成这一套（a2e5df76）。
- 界面不解释内部规则（分组依据写在代码里，不写成给用户看的说明）：用户要的是现状与下一步。界面上的叫法见 WORDS.md。

## 布局约束

- 工具栏内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 手机上系统菜单一弹出，输入法的候选栏就收起、键盘矮一截，贴着键盘的输入框会跟着往下掉、压到后面的列表上，选完再弹回来。所以输入框里的选择菜单（落点、交给谁、用哪个 Agent、模型、＋、发送钮长按、带上的卡片长按）都用 `MenuButton`，不用 SwiftUI 的 `Menu`：它挂在 UIKit 按钮上，知道菜单开着，这段里 `KeyboardHold` 把页面与浮起的输入框锁在原位；SwiftUI 的 `Menu` 不说它开没开。
- 推入页的底色铺在导航容器上，不铺在滚动区上：数据没到的几帧整页透明，会露出系统黑。
- 读库的修饰符要挂在一个真的视图上（读不出来时可以是 `Color.clear`）：当场读与订阅都等视图出现才启动，什么都不排它就不启动，页面永远空白（点通知进会话页曾如此）。
- 顶栏的工具栏项在推入时就建好、之后只换其中的内容，控件随数据置灰而不出现消失：推入转场期间系统不重建工具栏项，换项要等转场结束才显示，标题会晚到近一秒。
- 主导航的结构只有一份（`SidebarOutline`：Cue；任务、会话；置顶与最近的项目，末尾"全部项目"；归档、回收站、设置），各端只管长相。Mac 与宽屏 iPad 是侧栏。iPhone（与窄窗口 iPad）打开就是 Cue，底部永远一排（`DockRoot`）：任务、会话、项目三页的根上左边三格、右边 Cue 圆钮；Cue 页上那三格收成输入框左边的一颗"⋯"圆钮，点开原地展开成三页上 Dock 的样子（输入框收成右端一颗 Cue 头像的圆，有草稿时挂一颗牛皮纸色的小气泡，点它收回），输入框聚焦时让开。只有这四个去处是根，其余去处推在所属的那一页上（项目、归档、回收站、设置推在项目页上），换去处清掉推入的页；推入的页没有那一排（它们有自己的底），返回交给系统。Cue 是主入口，所以它占输入框那一整排、三页只占三格：换区一步到，底部只有一层。
- 页面顶上不写大标题：侧栏或底部那一排的选中格已经说了在哪一页（Mac 与宽屏 iPad 的任务页，顶上第一排就是按项目筛的胶囊与那一页的操作）。手机的顶栏每页按同一个规则摆，用户在哪一页都知道东西在哪：三页的根不写标题（底部那一排的选中格已经说了在哪一页，名字只交给读屏、返回菜单与多任务切换器），顶上那一排只有左边一颗搜索钮、右边这一页的那一个操作，内容第一行紧接在这一排下面；Cue 页的页头就是最上面铺满的一条；四个根都不用系统导航栏，顶上那一排是页自己画的，换去处时随页一起推；推入页左边返回，中间是对象名加一行要紧信息，右边只在有这个对象的操作时放"⋯"，只有一个操作就直接放那颗钮。顶栏不放状态图标与搜索框以外的输入。搜索各宽度都推在当前页上（窄屏搜索框在导航栏中间，宽屏在导航栏下面那一排），退出就是返回。App 的设置在项目页末尾、宽屏侧栏底部（同步出问题时那一行与底部的"项目"带点；Cue 自己的大脑与上下文只在 Cue 页头的面板里，它的设置从面板的齿轮与设置页第一行都推得进，同 Mac 上 Cue 页"⋯"里的"<它的名字> 的设置…"翻到设置窗口的 Cue 那一页，那一页的标签也写它的名字）。设置各端同一套分组与说法，按要紧排（Cue、iCloud 同步、通知、外观；Mac 另有快捷键、更新与接入 Agent），一项设置只在一处改：用哪个 Agent 与模型只在 Cue 页上。窄屏只有一个导航栈：换去处是根里的两页水平推移（新去处在底部那一排的右边就从右边推进来），新页先在屏外排好再动；底部那一排不跟着推，原地从旧的样子长成新的。不在几个导航栈之间换：导航栈托管在 UIKit 里，SwiftUI 不逐帧挪、淡它，旧页会停着到最后一下才走（闪回旧页）。
- 沉浸式顶部与底部：顶栏（返回钮、标题胶囊、圆钮，Cue 页头与搜索框那一排）直接浮在内容上，内容一直滚到它们后面：栏后面、栏下面都不加任何遮罩、渐变、模糊或底色，系统的滚动边缘效果关掉，每一页都一样（规矩在 `Bars`）。玻璃本身就是遮挡，再垫一层就是两层糊，还把内容遮住。返回钮与页头之间的窄缝里露出半截字也照样露着（整条顶栏后面的淡出加过、被用户撤回）。iOS 的内容一直透到屏幕最顶，只在状态栏那一条（屏幕顶到状态栏下沿）垫一层页底色的渐变（`RouteView` 一处）：时间、信号与电池那半截实，往下淡完，灵动岛以下的内容透出来。整条裁掉、只留页底色的做法用过，灵动岛下面那一截空着像被遮住，被用户撤回。
- Mac 上不用 NSWindow sheet（系统提示框与确认框也是）：sheet 开、关都把主线程关在约 300ms 的嵌套动画循环里。窗口内的浮层只有 `panel` 一种，确认框是 `dialog`，iOS 上同一个调用是系统 sheet 与提示框。关法只有一套：Esc 或在最上面那层外面按下鼠标（含工具栏）。这一下交不交给下面同系统：模态的接下；不模态的（任务气泡）照常落到下面。模态靠按键与点按的本地事件监听，不停用下面那层界面（停用整窗开、关各多 20～25ms），所以下面那层的页面不挂 ↩ 的快捷键；⌘K 与 ⌃⌘S（侧栏；⌘\ 常被 1Password 占作全局快捷键）是主菜单"显示"里的开关命令，开着时再按同一个键就关，同一组里的 ⌘⇧T 去任务页；浮层收起时焦点只交还给弹出前所在的输入框，不在输入框时不交还（交给 SwiftUI 的宿主视图会让它挑页面上第一个输入框）。
- 看一条任务只有任务气泡一种（`TaskBubble`，`panel` 的 `bubble` 样式）：从点的那一下长出来（两端都摆在那一行下面、让开整行，尾巴对着那一下，下面放不下摆上面；不摆左右：会盖住被点的行、尾巴落在字上；键盘、⌘K 里按 ↩、小组件链接没有落点时在上方居中），不压暗、不换页；点外面或 Esc 关，那一下照常落到下面，所以点另一条任务就是换成它的气泡；气泡里点步骤原地翻页。两端同一个视图与摆法（`BubblePlacement`），iOS 上也不是系统 sheet。Mac 不用系统 popover（实测）：它是另一扇窗，进程里第一次弹要 85～113ms（大库掉一帧 136ms），关时主窗口重新变回前台窗口、开销是窗口内浮层的 2～3 倍，开着时主窗口的快捷键不响应；窗口内的气泡开 30ms 上下、关 5～7ms。任务不再有整页与居中的浮窗。
- Mac 上开合不逐帧挪位置：侧栏开合一步到位，编辑页原地淡入淡出。位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，侧栏动画会掉帧十几次。有字的一块进出场不缩放：缩放的每一帧字都按新大小重画（Instruments 实测任务气泡开合各约 400ms 里主线程三成在重画字），挪一小段加淡入淡出，字只画一次。

## 加载与同步

- 本机库里的东西第一帧就是读到的样子，没有"还没读到"这一态：页面的读（`observing`）出现时在主线程当场读一次再接着订阅，项目目录、Cue 的现状（`Workspace.init`）与在线会话（`LiveSessions`）在建出来时当场读。不给页面加"读到没有"的标志、默认值与转圈；要等的只有别的设备（同步、向 Mac 取对话）。
- "这一页在等同步"只有 `AppServices.isCatchingUp` 一个来源，样子只在 `Pending.swift` 定：页头那一行写"正在同步"，"这里还没有"类的空态换成"正在从 iCloud 同步"；过了 `Pending.delay` 才出，回到前台的那一拉多在一秒内，一闪而过的指示比稍等更扰人。
- 正在对的期间到的新内容先不动正在看的（`ChatScroll` 的 `holding`），对完一次滑上来：一页一滑，整段对话会一路往下闪。排开到哪按那一条记，读的范围丢掉最早几条时上面已排的不被挤掉（`ChatColumn`）。
- 减弱动态效果：转圈换成静止的一段弧（`Spinner`），指示只淡入淡出，滑到最新直接到。

## 渲染性能约束

实测数字与细节在各类型的注释里；这里是原则。

- 滚动时每帧都变的读数（偏移）不进状态，只放会让状态改变的越线；行里不放 `GeometryReader`。每个几何读数都是一次布局回调，挂在每行上滚动就跟不上。
- 行数不封顶的列表用懒加载栈，懒加载栈里一组行的容器也要懒加载：滚动区里的普通栈在打开那一圈把所有行量一遍，Agent 整页历史曾因此三千条到 1.4GB。任务页看板的每一列各自是一个懒加载的滚动区（`BoardColumn`）。例外各在其类型里说明（Mac 侧栏、会话对话）。
- 按时刻换字的文字（计时、倒计时、"x 分钟前"）经 `LiveText`，只在字会变的那一刻重画：系统时间文本在 Mac 上窗口每画一帧都重画一遍，挂着看不见的页也算，滚动与动画的每一帧都替它们付钱。
- 分段的长文字（回答、你说的话、带上的全文）经 `Paragraphs` 排，不整串放进一个 `Text`：iOS 上一个 `Text` 的排版随段数乘全串长度增长，8000 字的回答排一次 1.7 秒，会话页一打开就把主线程占住好几秒。
- 输入框里每敲一个字的开销不随草稿长度增长（粘贴几百行进来曾每个字卡两三百毫秒）：文字区的高度只排撑满上限的那段开头（`ComposerHeight`）；交给草稿的字先转成原生字符串（桥接来的 NSString 上每次读都逐字走慢路）；更新时不拿整串比较、不重设整篇的属性（设一次颜色就是整篇重铺、重排）；草稿的读者（预览、是否命令）只看开头；iOS 文字区在粘贴、外部写进之后整篇排一遍（只排看得见的那段时估的高度一直在变，系统追着光标一帧帧地滚）。
- 卡片上不用渐变描边：`strokeBorder(LinearGradient)` 由 CPU 按整张卡面积铺渐变，卡片一变宽整面墙重画，大库里开合侧栏第一帧曾卡到约 150ms。渐变只用在填充上。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图：读了就是整窗或整面墙跟着重算。
- 第一次打开页面的那一帧只建看得见的：`ViewThatFits` 会把挑剩的候选也建出来（"等你"卡曾因"内容"与"滚动区里的内容"两份多建约 120M 条指令），能按尺寸定的用 `Layout` 一次排；`Canvas` 第一次画一张就要几毫秒，几道线、一个环用 `Shape`；打开后紧接着的重活（往上再排开一段、生成缩略图）等这一帧画上屏（`NextFrame.drawn`）。
- 会动的过渡里，重活（建编辑器、挂底栏、让编辑器接过键盘）放在动之前、每帧一步：动起来之后每帧只剩动画与改透明度，才不掉帧。
- Pi 状态的变化是最常见的整树重算来源：视图读自己要的那个会话（`pi.session(sessionID:)`），只关心有哪些会话读 `pi.slots`，读 `pi.sessions` 的只有必须看全部状态的地方；会话行与侧栏项目行是 `Equatable` 的，调用处挂 `.equatable()`。
- 每天开很多次、建起来又贵的浮层（⌘K）与工具栏里内容多的菜单常驻，收起只是隐藏；其余浮层开时才建。常驻省的是每次几十毫秒的重建，代价是常驻的内存。
- 列表行里成百上千的小点按目标（完成圈，`TaskCheckButton`）在 Mac 上不用 `Button`（`ListPress`）：每颗带一套焦点、按键与读屏的机器，150 条任务一次展开约多 55M 指令；其余照按钮：读屏是按钮、点进没激活的窗口的那一下不算（`FirstClick`）、全键盘访问打开时能 Tab 到与空格按下。
