# 界面约定

## 视觉原则

- 内容是纸，控件是玻璃：灵感与任务的卡片是纸色实底；栏头与页顶的控件、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。用户靠这个一眼分清内容和操作。
- 每多一档颜色，就多一样要用户分辨的东西；石绿不再给第三种事。
- 选中不用靛青：选中说的是"这里放着它"，不是"这里有动静"，全 App 只有一种中性淡底（`Palette.selection`，比悬停深一档）加墨字（字半粗），靛青铺成一块底会压过真正在跑的那几条线。
- 项目色只上图形，不写成字、不做成圆点：圆点和彩字会被读成状态。
- 图标默认不套装饰圆底：分组标题与项目标直接给字形着色；等你用裸问号，实心圆徽只强调失败。任务待办是空圈、进行中是静止开口弧（不表示百分比），有子任务时分段环才表达真实完成比例，原生圆钮表达操作容器，两者不属于图标装饰，不一并去掉；圆钮内部不重复套装饰圆。
- 同一状态处处同一个样子，用户只学一次：新界面引用现成的状态图形，不另画。对勾只表示完成与记下。
- logo 就是 Cue 本人：App 图标、菜单栏、图标族、落地页同一个形象。
- 灵动岛是例外的小视口。扩展只在内容更新时过渡，不移植 App 的循环头像，也不为动画发推送；系统将动画限制在两秒内，Always-On 低亮度时不播（[Apple](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities)）。
- 系统菜单里的标志要显式标为可见：macOS 27、iPadOS 27 起默认藏起菜单项图片。
- 看板分轻重：推进中、等你是此刻要看的，重；待办、已完成是清单与回顾，轻。
- 切页只有一种（`Motion.turn`）：分段里靠右的、往里翻的从右边进，靠左的、返回的从左边进，只滑一小段并淡入。
- Mac 照原生控件：单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。和系统应用不一样的地方，用户会觉得是坏了。
- 悬停：悬停时要换颜色、露记号的按钮读 `buttonHovered`，不各自挂 `onHover`；系统控件的悬停与焦点环交给系统。
- 列表行之间不画分割线，靠间距与纸分组（系统 `Form` 与菜单除外）。
- 悬停、选中时才出现的东西不改动周围的排版：随选中变的只换颜色与字重、不插不撤占位置的东西。露出一个钮挤动了标题与时间、选中一格让整条会话条上下跳，都是用户能一眼看见的抖。
- 少写字：不写说明句与次级标签，要解释的放问号气泡。

## 栏头与页顶

- 布局只有窄屏、宽屏，按可用宽度选、不按系统分：Mac 是宽屏，iPad 窄窗同手机、宽窗同 Mac。
- 栏头不放导航，只放 `Workspace` 里已有的状态；读不到页面读的库就不抄一份（那是第二个事实源）。低频操作进"⋯"。
- 系统导航栏只给推入的页：左缘右滑返回是系统的，所以推入页不藏系统导航栏。
- 浮动导航的边缘处理归 `Bars` 与导航容器，不在各页重复：顶部用系统 `soft` 滚动边缘效果，不另加遮罩、装饰底或随滚动变化的状态；用 `fadesUnderHead` 的栏关掉自己的原生顶部边缘效果，避免叠加；预览页例外：栏后面上下都不垫系统的滚动边缘效果，分页（`PreviewPager`，`TabView` 分页那一层由 `PreviewDismissGuard` 关）与缩放的滚动区（`PreviewZoom`）各自关掉。

## 页面与布局稳定

- 栏头与工具栏的内容只随用户操作与数据变，不随滚动位置、尺寸等布局读数变。几何读数（`onGeometryChange`、`onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 容器多大只看它是什么，不看里面填了多少：空、少、满同一套尺寸，可选的那一行没有也占着位置，计数原地换数。内容一变整块就缩、就跳，用户读作出了什么事。列表的行随条数增减，不变的是每一行、每一块自己的尺寸。会出现的行预留位置或叠在上方（`ChatLiveSlot`、`composerNotice`、`RiseBehind`）。
- 滚动区内容的边用 `safeAreaPadding`，不用 `contentMargins(…, for: .scrollContent)`：同一棵树里几块滚动区在同一次更新里定内容边距时，SwiftUI 会把一块的边距写到另一块上、之后不改回。滚动条要贴原来的边就用负的 `contentMargins(…, for: .scrollIndicators)` 抵回。唯一例外是清掉系统列表默认顶边的 `contentMargins(.top, 0)`（`RouteView`）：安全区加不出负数。
- 读库的修饰符（`observing`）挂在一个真的视图上，读不出来时可以是 `Color.clear`：订阅等视图出现才启动，什么都不排它就不启动，页面永远空白。
- 开着时才有的透明接点层（点面板外收起）用 `.transition(.identity)`，收起那一下就撤：跟着收起的动画走的话，淡完之前它还接点按，紧接着点下面的东西会点在它上面。
- 设置各端同一页、同一套分组；一项设置只在一处改。

## 浮层、菜单与气泡

- Mac 上不用 NSWindow sheet：开、关都把主线程关在约 300ms 的嵌套循环里。窗口内的浮层只有 `panel`，确认框是 `dialog`（`Panel+macOS.swift`）。
- 系统 popover 关时主窗口重新变回前台窗口；窗口内的气泡开约 30ms、关 5～7ms（实测）。
- 菜单一律系统菜单（`contextMenu`、`Menu`），每类对象一份内容；挂菜单的那一层不包在定时重画的容器里。
- 顶栏长出的面板（`GrowPanel`）里不放滚动区：会被写上页面滚动区的内容边距（上面 `safeAreaPadding` 那条）。

## 宽屏开合

宽屏开合不逐帧排版（Mac、iPad 同一套）：会话条、Cue 开合与跨临界宽时几块这一下就到终点、页按新宽排一次，看得见的滑动全是渲染端叠在图层上的偏移，动画里主线程没有活。做法与否决过的方案在 `WideColumnSlide`、`WideSlide` 的头注释。有字的一块进出场不缩放（理由在 `Bubble.swift`）。

## 渲染性能约束

- 滚动时每帧都变的读数（偏移）不进状态，只放会让状态改变的越线；行里不放 `GeometryReader`。每个几何读数都是一次布局回调，挂在每行上滚动就跟不上。
- 行数不封顶的列表用懒加载栈，懒加载栈里一组行的容器也要懒加载：普通栈打开时把所有行量一遍。例外各在其类型里说明（会话条的分组、会话对话）。
- 输入框每敲一个字的开销不随草稿长度增长：不拿整串比较、不重设整篇的属性，草稿的读者（预览、是否命令）只看开头。
- 卡片上不用渐变描边：CPU 按整张卡面积铺渐变，卡片一变宽整面墙重画。渐变只用在填充上。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图。
- Pi 状态的变化是最常见的整树重算来源：视图读自己要的那个会话（`pi.session(sessionID:)`），只关心有哪些会话读 `pi.slots`，读 `pi.sessions` 的只有必须看全部状态的地方；会话行是 `Equatable` 的，调用处挂 `.equatable()`。
- 第一次打开页面的那一帧只建看得见的：`ViewThatFits` 会把挑剩的候选也建出来，能按尺寸定的用 `Layout` 一次排；`Canvas` 第一次画一张就要几毫秒，几道线、一个环用 `Shape`；打开后紧接着的重活等这一帧画上屏（`NextFrame.drawn`）。
- 先排后动：会动的过渡里，重活（建页、建编辑器、让编辑器接过键盘）放在动之前、每帧一步，动起来之后每帧只剩动画与改透明度。
- 逐行、逐格跑的代码不用正则字面量：每求值一次就新建一份、第一次匹配时再编译（拆 Markdown 曾每行编译三遍）。
