# 界面约定

跨界面的原则与理由。具体界面的样子与规则在各视图类型的头注释里；颜色令牌在 `Palette`，字号、间距、动效与表面在 `UI/Shared/Theme/`。能写成检查的规则在 `apple/scripts/lint.sh`，原因写在它的报错里。

做新界面或视觉改动时，先读 ui-craft 与 ui-picks 两个 skill，先出原型或截图给用户看，再出文字方案。

## 视觉原则

- 内容是纸，控件是玻璃：灵感与任务的卡片是纸色实底；工具栏、侧栏、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。用户靠这个一眼分清内容和操作。
- 颜色只有一份 `Palette`，纸与墨、签名色、状态色、项目色各管什么写在它的头注释里。每多一档颜色，就多一样要用户分辨的东西。
- 石绿有两种用途：会话有新回复，与任务做完（完成对勾、看板已完成那一列的记号）。两者说的都是"这一轮做完了，结果在那儿"，一个落在会话上、一个落在任务上，同一屏里读不混；不再给第三种事。
- 字是墨，分三档（`ink`、`ink2`、`ink3`），三档都是要读的字，在各层底与实底玻璃上都 ≥ 4.5:1；不用系统灰与系统占位色。
- 签名色靛青只给焦点与正在发生的事，一屏一两处。在跑与选中都是"这里有动静"，靠形状分：在跑是会动的线，选中是一块底。
- 项目色只上图形，不写成字、不做成圆点：圆点和彩字会被读成状态。
- 同一状态处处同一个样子，用户只学一次。每种图形只有一个出处：任务圈 `TaskRingView`（有子任务的按子任务分段，做到哪只画在圈上、不另写"n/m"）、任务行 `TaskLine`（项目页，要你管的才写状态词）、看板卡（`BoardTaskCard`、`BoardSessionCard`、等你列的 `BoardWaitCard`，推进中卡下沿的线 `BoardLine` 只按 `BoardPulse` 画）、会话状态 `PiShown`、出错 `FailureMark`、等你 `Waiting.swift`（拍板赭黄；待回复是墨点，会话行、待回复提示、看板卡与经过里同一个，出自 `PiShown.icon`）、一件拍板怎么答 `WaitAnswer`（Cue 页拍板卡、会话页问题卡同一个，按问题种类给；进展页只看不答）；新界面引用它们，不另画。对勾只表示完成与记下。
- 图标只经 `Icon`，品牌标志只经 `BrandMark`，规则在各自头注释里。"发出"（发送、作答、交给、发往 Mac）是纸飞机，只表示方向的（在上面、更早、回到最新）是胖箭头，两族不互借。系统菜单里的标志要显式标为可见：macOS 27、iPadOS 27 起默认藏起菜单项图片。
- 对话里只有说的话是一块（气泡），块只另给要你操作的卡片（拍板、启用）；其余是不铺底、不描边的旁注与居中标记（`ChatMargin.swift` 头注释）。一眼分得出哪句是对你说的。
- 写着字的玻璃垫实底（`GlassInk.solid`）：内容滚到玻璃后面，背后可能是亮图也可能是深色代码块，只着色的玻璃上字读不出来；垫了底才在任何背景上都够 4.5:1。
- 动效告诉用户东西去了哪，不是表演：位移与尺寸用无回弹弹簧、不超过 300ms，唯一例外是 Cue 与会话之间的接力（`CueRelayStage`）。数值与减弱动态效果的规矩在 `Motion`。
- Mac 照原生控件：按下即变淡、不缩放不震动（`PressFeedback`）；指针照 HIG 与访达、邮件，按钮、行与卡片都是箭头，手形只给打开网页的链接（手形在 Mac 上读作"这是网页"）；单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。和系统应用不一样的地方，用户会觉得是坏了。
- 悬停：点得到的东西指针一过就有回应（同 macOS 26 工具栏的玻璃钮、Linear、Arc）——自绘的按钮浮一层淡底、卡片亮一档、行铺淡底，淡入淡出、不挪位置不缩放；只经 `PressStyle`（按种类 `Press`）与 `RowStyle`，自绘的可点控件不用 `.plain`、`.borderless`（`lint.sh` 查），悬停时要换颜色、露记号的按钮读 `buttonHovered`，不各自挂 `onHover`；浮在内容上的玻璃胶囊与圆钮只经 `ControlButtonStyle`（`glass`、`circular`）。系统控件的悬停与焦点环交给系统；iPad 的指针同一套（行同 Mac，按钮用系统的悬停效果）。
- 项目联动（Mac）：指针停在侧栏的项目行或看板卡上的项目小图形上时，看板上别的项目的卡淡下去，同一项目的不动。指着哪个项目只有 `Workspace.hoveredProject` 一份，侧栏与看板读写同一份（`boardDim`）。
- 悬停、选中时才出现的东西不改动周围的排版：悬停才露的操作只经 `hoverReveal` 浮在行上，随选中变的只换颜色与字重、不插不撤占位置的东西。露出一个钮挤动了标题与时间、选中一页让整列侧栏上下跳，都是用户能一眼看见的抖。
- 列表行的选中、按下与悬停底只有 `RowStyle` 一份，调用处只说"这是一行"，不自己画底、圆角与负边距。
- 少写字：不写说明句与次级标签，要解释的放问号气泡；撤不回的后果写在按钮旁。叫法见 WORDS.md。

## 布局约束

- 工具栏内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 布局要稳定：容器多大只看它是什么，不看里面填了多少——空、少、满同一套尺寸；可选的那一行没有也占着位置，计数原地换数、不让一行出现又消失。内容一变整块就缩、就跳，用户读作出了什么事，眼睛还得重新找。例：竖屏 iPhone 的进展页四行铺满顶栏到底部，行高只由这段高定，空行、卡多卡少都不改（`PhoneBoard`；横屏同 iPad、Mac 四列：列最窄 160，放不下四列时（如窄窗开着侧栏）横向滚动、最右一列露出一截，`BoardColumns`）；卡留足标题行数、四列等高（`BoardCardMetrics`）；页顶那一排中间那块玻璃先定高再上玻璃，项目没写介绍也与两侧圆钮同高（`HeaderPiece`）；同样的还有 Mac 项目页顶的介绍行（`ProjectPage`）、置顶项目卡与"更早"行的第二行、Mac 侧栏的 Cue 名片（`CueSidebarCard`）。列表的条数是内容，行随条数增减；不变的是每一行、每一块自己的尺寸。
- 滚动区内容的边用 `safeAreaPadding`，不用 `contentMargins(…, for: .scrollContent)`：同一棵树里几块滚动区在同一次更新里定内容边距时，SwiftUI 会把一块的边距写到另一块上、之后不改回，安全区的边每次排版重算。滚动条要贴原来的边就用负的 `contentMargins(…, for: .scrollIndicators)` 抵回。唯一例外是清掉系统列表默认顶边的 `contentMargins(.top, 0)`（`RouteView`）：安全区加不出负数。
- 手机输入框里的选择菜单用 `MenuButton`，不用 SwiftUI 的 `Menu`：菜单一开键盘变矮，输入框会掉下去再弹回（理由在它的头注释）。
- 读库的修饰符（`observing`）挂在一个真的视图上，读不出来时可以是 `Color.clear`：订阅等视图出现才启动，什么都不排它就不启动，页面永远空白。
- 顶栏的工具栏项在推入时就建好、之后只换内容，控件随数据置灰而不出现消失：推入转场期间系统不重建工具栏项，换项要等转场结束才显示，标题会晚到近一秒。
- 主导航的结构只有一份 `SidebarOutline`，各端只管长相。窄屏（iPhone 与窄窗口 iPad）打开就是 Cue，底部那一排整个窗口一份（`DockRoot`）：项目、进展两格，加占两格宽的 Cue 钮（会话在进展里，没有单独一格），扫一眼就知道几件推进中、几件等你；Cue 是主入口，在 Cue 页上 Cue 钮长成输入框、两格收成"⋯"。推入的页上这一排照样在（同系统标签栏），会话页、卡片纸页与技能与规则页它让开（`Dock.stays`），浮起的输入框（新会话、发给 Agent）开着时也让开，不与输入框叠两层玻璃。根上三页按这一排的顺序横排，左右滑跟手切页；推入的页右滑返回是系统的，回到 Cue 页后左滑前进回刚才那页（`HomePager`）。横拖的归属一条规矩：手指下还能往那边滚的内容先滚，行上慢慢拖开是行的动作，快甩、贴屏幕边起手、滚到头之后、手指下横着滚不动的地方（进展页看板的行与行之间、空行、行尾）是切页与返回（`PagerArbiter`、`rowSwipes`），各页一样。切页只有一条路、一条弹簧：拖、松手、点按、深链都经 `PagerController`，每帧只挪一条图层（三页各在自己的托管控制器里，页里不经 SwiftUI）；条在哪只有一份（`PagerMotion`），底部那一排的选中（过半换格）与从两格到"⋯"加输入框的换形都读它。两格是系统标签栏（`DockTabs`）：按住拖动的液态透镜、读屏与大内容查看器是系统的，自绘的玻璃拿不到；换形里它只淡入淡出，淡完 Cue 钮才长成输入框（`DockHandoff`）。
- 页面顶上不写大标题：侧栏或底部那一排的选中格已经说了在哪一页；iPad 侧栏不在旁边（收起，或从左缘滑出盖在页上）时，根页照推入的页写页名与介绍。Mac 不另起页顶那一排：Workspace 里已有的状态与整个 App 的收进窗口最顶那一排的工具栏，控件常驻、只换内容（工具栏读不到页面的数据，抄过去就是第二个事实源；工具栏项一增删整条重建，实测占切页的三成到一半），左右各并成一项（`LeadingSlots`、`TrailingSlots`：宽 0 的项也占一格圆钮宽）。只在一部分时候有的控件（侧栏收起时的项目切换、进展页的分段、范围、额度环、新会话）不在时宽 0（`toolbarPresence`），进展页的那几样随进展页第一次挂上才建（`ProgressControl`，冷启动的第一帧不建），进出进展页整条重排一次；同一页里换段只换看得见的（`toolbarVisible`），宽度不变。中间的标题位按窗口宽让（`ToolbarItemFlex`），窗口最窄时也不把控件挤进溢出菜单。状态归页面的（会话段的搜索框）留在页里，其余操作在右上"⋯"。进展页两段左上同一组看板｜会话图标（`PanesSlot`，同手机顶上那块玻璃里的那一组）：看板段那一排其余只有四个列头、各对齐自己那一列（`boardTopRow`），项目范围、新任务收进"⋯"（选了项目时"⋯"角上带它的图形）；会话段那一排是项目范围、额度环与新会话；两段的搜索都在"⋯"里，侧栏收起时也不放当前页胶囊（分段已说了在哪一页）；iPhone 与 iPad 的页顶那一排只有一种（`floatingHeader`）：左右各一颗圆钮、中间一两块，各是一块玻璃，玻璃之间透出内容；根页的那一排页自己画，系统导航栏只给推入的页，推入时根的那一排随页让出、不与推入页的栏项交叉滑动。推入页左边是系统的返回（左缘右滑返回是系统的，所以推入页不藏系统导航栏），手机进展页左边是搜索钮，iPad 根页左边是侧栏钮（系统的撤掉；收起时 Cue 有事角上带点，同 Mac 的侧栏钮）；右边只放这一页自己的操作，iPad 右侧 Cue 面板的开关在侧栏 Cue 那一行。不放状态图标与搜索框以外的输入，同一屏不重复写这一页的名字。根页中间只放这一页看什么：进展页是看板｜会话、项目范围（两段共用一份 `Workspace.projectScope`，换段不丢）与额度环并成的一块；Cue 页只有 Cue 的名牌（定宽定高，头像在左占两行、名字与数字账在右，比圆钮高一截，对话按它让出：数字账随时在变，跟着变宽整颗就一直在动）；项目页是一条搜索框（点了进搜索页），从左页边铺到"新建项目"圆钮前，放大镜正落在进展页搜索钮的位置，左右切页时不跳；提示横幅盖住它时与它同一范围（`HeaderSearch`）。
- 手机与 iPad 上从顶栏长出的面板（Cue 的名牌、进展页的额度环）只有 `GrowPanel` 一种：同一块玻璃原地长大，点外面收回，不退成系统弹出框（导航栏里的项画不到栏外，所以有面板的页都是根页、那一排页自己画）。两侧圆钮之间放得下就停在手机那一档宽、居中让出圆钮，放不下就铺满、整颗盖住，不露半颗。面板里不放滚动区：会被写上页面滚动区的内容边距（上面滚动区内容的边那条）。Cue 的面板只放 Cue 自己的、会天天变的（列在 `CueNowPanel` 头注释），空、少、满与启用前后一个尺寸；在做的会话在进展页的会话段，从那里进会话，返回落点与行的长相都只有一种。Mac 上开合不逐帧长大（下面"Mac 上开合"那条），额度明细是从额度环长出的气泡。
- Cue 的现状各处一个样子（名牌、侧栏、菜单栏、小组件、灵动岛与锁屏，规则在 `CueNow` 与 `CueBeat`）：头像没有环，在动、起不来是右下一颗点，不在整个变淡；第二行是数字账（拍板赭黄、待回复墨色、推进中与子代理靛青），不挑一句、不用珠子；App 图标与菜单栏图标的角标是"等你 N"（拍板加待回复，`CueNow.needsYou`）。
- 开着时才有的透明接点层（点面板外收起、点别处收回）用 `.transition(.identity)`，收起那一下就撤：跟着收起的动画走的话，它淡完之前还接点按，收起后紧接着点下面的东西会点在它上面（Cue 面板就这样被点开回来过）。
- 设置各端同一页、同一套分组与说法，按要紧排：最上面一组是 Cue（组名是它的名字，只有名字与在哪台 Mac 上运行两行），下面是 iCloud 同步、通知、外观；Mac 设置窗口只有通用与 Agent 两页，Cue 那组在通用页最上面。一项设置只在一处改：用哪个 Agent 与模型只在 Cue 页上。选在哪台 Mac 上运行的菜单各入口同一份（`CueHostMenu`）。
- 沉浸式的栏：页顶那一排与页里钉住的一块（看板列头与手机看板的行头、分段、筛选）都浮在内容上，内容一直滚到它们后面、从玻璃之间和玻璃里透出来。它们后面、下面不加遮罩、渐变、模糊或底色，滚动区也不从它们的下沿开始（那等于把内容裁在下沿）。窗口最顶那一条：Mac 的工具栏那一条同样什么都不垫；iPhone、iPad 的状态栏那一条是系统的渐进模糊，整个窗口一份，顶上最糊、到状态栏下沿减到不糊，不着色、不垫底，时间与电量才不和滚过去的字叠在一起。用户定的，撤回过两次；规矩在 `Bars`。
- Mac 上不用 NSWindow sheet、`NSAlert`、`runModal`（`lint.sh` 查）：开、关都把主线程关在约 300ms 的嵌套循环里。窗口内的浮层只有 `panel`，确认框是 `dialog`；关法、模态与焦点交还在 `Panel+macOS.swift`。
- 气泡（`PanelStyle.bubble`）的来源只有 `BubbleSource` 一份，摆法一份（`BubblePlacement`）：从控件（按钮、圆钮、胶囊）弹出的挂在控件的框上（Mac 用 `bubble(isPresented:)`，控件自己量框），点、键盘、读屏打开都在同一处；从一行里点开的（任务行、任务行左滑的"更多"）用按下的那一点、按行高让开整行，行成百上千，不给每行挂几何读数。都没有时在窗口上方居中。手机（窄屏）的任务气泡不对着来源，是贴在底部的纸（`bottom`）。
- 看一条任务只有任务气泡（`TaskBubble`）；点任务行与看板卡时，开工了的叶子直接进它的会话、其余开气泡（`Workspace.enter`）：开工后要看的是会话里的进展。Mac 上也不用系统 popover：它是另一扇窗，进程里第一次弹要 85～113ms，关时主窗口重新变回前台窗口，开着时主窗口的快捷键不响应；窗口内的气泡开约 30ms、关 5～7ms（实测）。
- Mac 上开合不逐帧挪位置：位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，会掉帧十几次。侧栏开合时分栏在按下的那一下不带动画地换到终点、页按新的宽排一次，看得见的滑动由 Core Animation 在渲染端平移分栏的图层，页的左缘贴着侧栏走，动画里主线程没有活（`SidebarSlide`，工具栏里随侧栏摆的项按同一条曲线随侧栏滑；SwiftUI 的偏移与几何效果同样每帧重排，不用），编辑页原地淡入淡出；有字的一块进出场不缩放（理由在 `Bubble.swift`）。

## 加载与同步

- 本机库里的东西第一帧就是读到的样子，没有"还没读到"这一态：不给页面加"读到没有"的标志、默认值与转圈（`observing`）。要等的只有别的设备。
- "这一页在等同步"只有 `AppServices.isCatchingUp` 一个来源，样子只在 `Pending`。一闪而过的指示比稍等更扰人，所以过了 `Pending.delay` 才出；Mac 设置里同步那一行的"正在同步…"同理（`AppServices.shownSync`），一句话传上去的零点几秒不闪。
- 对同步期间到的新内容先不动正在看的，对完一次滑上来（`ChatScroll` 的 `holding`）。

## 渲染性能约束

实测数字与细节在各类型的注释里；这里是原则。

- 滚动时每帧都变的读数（偏移）不进状态，只放会让状态改变的越线；行里不放 `GeometryReader`。每个几何读数都是一次布局回调，挂在每行上滚动就跟不上。
- 行数不封顶的列表用懒加载栈，懒加载栈里一组行的容器也要懒加载：普通栈打开时把所有行量一遍。例外各在其类型里说明（Mac 侧栏、会话对话）。
- 按时刻换字的文字经 `LiveText`，分段的长文字经 `Paragraphs`，输入框的高度经 `ComposerHeight`：开销与理由在各自头注释里。输入框每敲一个字的开销不随草稿长度增长：不拿整串比较、不重设整篇的属性，草稿的读者（预览、是否命令）只看开头。
- 卡片上不用渐变描边：CPU 按整张卡面积铺渐变，卡片一变宽整面墙重画。渐变只用在填充上。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图。
- 常驻的循环动效（心电线、两颗点、小人帧序列…）只经 `LoopLayer` 交给 Core Animation：SwiftUI 的 repeatForever 每帧在 App 进程里重算。小人换帧次数即静置开销（`CueSprite`）。放不放只看 `LoopsPlay`（页不在前台、减弱动态效果、省电时不放；Mac 窗口露着、没焦点也照放），一列在动的线有上限（`BoardLine`）。别拿 `scenePhase` 判前台：Mac 的窗口由 AppKit 托管，它一直不是 active。
- 第一次打开页面的那一帧只建看得见的：`ViewThatFits` 会把挑剩的候选也建出来，能按尺寸定的用 `Layout` 一次排；`Canvas` 第一次画一张就要几毫秒，几道线、一个环用 `Shape`；打开后紧接着的重活等这一帧画上屏（`NextFrame.drawn`）。
- 先排后动：会动的过渡里，重活（建页、建编辑器、让编辑器接过键盘）放在动之前、每帧一步，动起来之后每帧只剩动画与改透明度。
- 逐行、逐格跑的代码不用正则字面量：每求值一次就新建一份、第一次匹配时再编译（拆 Markdown 曾每行编译三遍）。
- Pi 状态的变化是最常见的整树重算来源：视图读自己要的那个会话（`pi.session(sessionID:)`），只关心有哪些会话读 `pi.slots`，读 `pi.sessions` 的只有必须看全部状态的地方；会话行与 Mac 侧栏项目行是 `Equatable` 的，调用处挂 `.equatable()`。
- 每天开很多次、建起来又贵的浮层常驻，收起只是隐藏（`keptPanel`）；其余浮层开时才建。
- 列表行里成百上千的小点按目标在 Mac 上不用 `Button`，用 `ListPress`。
