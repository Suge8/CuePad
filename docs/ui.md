# 界面约定

具体界面的规格在各视图文件的头注释里；令牌在 `UI/Shared/Theme/`（`Palette`、`Typography`、`Surfaces`、`LoopLayer`）。这里只记跨界面的原则和不明显的约束。

## 视觉原则

- 内容是纸，控件是玻璃：纸感品牌留在卡片与底色上（灵感与任务的卡片是纸色的实底）；Mac 打开卡片的编辑页铺满内容区、与页面同底色，不画纸边、圆角与阴影，字限在一列可读行宽里居中，开合原地淡入淡出、不做几何动画；工具栏、侧栏、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。自绘玻璃只经 `glass(in:)`，材质一律 `.regular`（`.clear` 几乎不糊开背后的字，栏上的标题、标签与问题卡读不出）。
- 底子是纸与墨（logo 与吉祥物的两种颜色），三层同一色温由深到浅：侧栏 < 桌面 < 纸，深色是"夜里的纸"。文字、图标与系统控件的 tint 是墨。
- 签名色靛青（`signature`）只落在焦点上，一屏通常一两处：主按钮与发送钮、选中项的浅底、iPhone 底部栏选中的那一格、选中的筛选胶囊。在动的状态不占签名色，靠形状与动效；其余彩色只表示要你注意的状态（等你确认赭黄、出错胭脂，再配形状）与项目，赭黄不借给别的用途。
- 状态图形全 App 只有一份：任务只按 `TaskGlyph` 着色，任务圈只有 `TaskRingView`，会话状态标只有 `PiStateDot`；有新回复是墨色实心点，对勾只表示完成与记下。
- 玻璃上写着要读的字时用 `GlassInk.legible`；浮在一整片字上、自己也写着字的（提示横幅、浮起的输入框、手机会话页的回复框、Mac 底部输入栏、任务面板）用 `GlassInk.solid`。输入框的提示字一律 `Palette.placeholder`。"降低透明度""增强对比度"开启时退回实底。
- 动效：位移与尺寸用无回弹弹簧，不超过 300ms（令牌在 `Motion`）；按压只有三类（`PressStyle`、`RowPressStyle`、系统玻璃主按钮）；`PressStyle` 的调用处只给语义种类（`Press`：圆钮、控件、卡片、整宽的一条），两端写法相同，每种的样子只在 `PressFeedback` 一处定：手机按种类缩放回弹加轻触感，Mac 照原生控件按下即变淡（卡片压暗）、松开即复原，不缩放、不回弹、不震动；常驻循环动效只有 `LoopLayer` 里那几种，用 Core Animation（SwiftUI 的 `repeatForever` 与符号动效每帧在 App 进程里重算，静止的 Agent 页也占约 9% CPU）；等待的转圈用 `Spinner`，不用系统 `ProgressView`；减弱动态效果时退为短淡入淡出。
- Mac 指针与悬停照访达、邮件：按钮、行与卡片都是箭头，手形只给打开链接的字（`pointerStyle(.link)`）；系统控件与工具栏项的悬停、焦点环交给系统，自绘的只在悬停才露出东西的地方给反馈（行尾露出的动作、卡片浮起一层阴影、列表行的淡底），悬停不挪位置；单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。
- 字体：中文正文一律苹方。字号、行距与 Mac 页面间距只在 `Typography`、`Spacing` 按角色定义，界面里不另写字号；Mac 没有动态字体且系统样式偏小，按角色给固定字号、比系统高一档。
- 空态与出错页一律是吉祥物加一句现状（`EmptyState`），不用系统 `ContentUnavailableView`。
- 措辞：界面不解释内部规则（分组的依据写在代码里，不写成给用户看的说明）；界面上只说 Agent，Pi 会话叫"Agent 会话"，"Pi"只用于 Pi 这个产品本身（安装、升级、连接、扩展、版本、模型与 `pi` 命令）。

## 布局约束

- 工具栏内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 推入页的底色铺在导航容器上（`containerBackground(_:for: .navigation)`，iOS 在 `RouteView` 一处铺），不铺在滚动区上，否则数据没到的几帧整页透明露出系统黑。
- 顶栏的工具栏项在推入时就建好、之后只换其中的内容，控件随数据置灰而不出现消失：推入转场期间系统不重建工具栏项，换项要等转场结束才显示，纸页标题会晚到近一秒。
- 沉浸式顶部与底部：内容一直滚到顶栏、搜索那一排、底部栏与回复框的玻璃后面并清楚可见，只有滚进状态栏时间与图标那一段的内容淡出（`fadesUnderBars`，内容的透明度遮罩；Mac 是工具栏下沿那一小段），栏后面与下沿都不垫模糊或渐变带，系统的滚动边缘效果关掉；遮罩只随页面在屏幕上的位置变，不读滚动位置。静止时第一行离栏的距离是内容边距，只有 `Bars.contentGap` 一处。
- Mac 上不用 NSWindow sheet（系统提示框与确认框也是）：AppKit 的 sheet 开、关都把主线程关在约 300ms 的嵌套动画循环里。窗口内的浮层只有 `panel` 一种（每个窗口根上挂一次 `panelHost`），确认框是 `dialog`，iOS 上同一个调用是系统 sheet 与提示框。模态靠按键与工具栏点按的本地事件监听，不停用下面那层界面（停用整窗开、关各多 20～25ms），所以下面那层的页面不挂 ↩ 的快捷键；⌘K、⌘⇧T 与 ⌃⌘S（侧栏，macOS 标准键；⌘\ 常被 1Password 占作全局快捷键）是主菜单"显示"里的开关命令，开着时再按同一个键就关；浮层收起时焦点只交还给弹出前所在的输入框，不在输入框时不交还（交给 SwiftUI 的宿主视图会让它挑页面上第一个输入框）。
- Mac 上开合不逐帧挪位置：侧栏开合一步到位（`MacPages.toggleSidebar`，不走 AppKit 的分栏动画），任务面板、编辑页原地淡入淡出。位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，侧栏动画会掉帧十几次。

## 渲染性能约束

- 大量行的区域用懒加载栈，懒加载栈里一组行的容器也要懒加载（Agent 整页历史曾用普通 VStack，三千条历史滚到底内存到 1.4GB）。
- 卡片上不用渐变描边（`strokeBorder(LinearGradient)` 由 CPU 按整张卡面积铺渐变，卡片一变宽整面墙重画，大库里开合侧栏的第一帧曾卡到约 150ms），渐变只用在填充上。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图。
- 会动的过渡里，重活（创建编辑器、挂底栏、让编辑器接过键盘）放在动之前、每帧一步，动起来之后每帧只剩动画与改透明度。
- Pi 状态的变化是最常见的整树重算来源：桥上的会话一个会话一格（`PiBridge.Slot`），视图读自己要的会话用 `pi.session(sessionID:)`；只关心有哪些会话读 `pi.slots`；读 `pi.sessions` 的只有必须看全部状态的地方。会话行（`PiSessionRow`）与侧栏项目行是 `Equatable` 的，调用处挂 `.equatable()`。
- 悬停开关若会换掉子视图（`selectableOnHover`），悬停不用 SwiftUI 的 `onHover`：平台视图盖到指针下面时它立刻报"离开"，开关关掉、平台视图撤走、又报"进入"，每秒几千次，主线程被占死；改用 AppKit 跟踪区（`HoverSensor`）。
- 卡片摘要（`CueSummary`）只读到标题之后第一段的末尾，不解析每张卡的整篇正文。
- 滚动区里的普通栈要在打开的那一圈把所有行量一遍（滚动区查内容大小不止一次）：行数不封顶的列表要么懒加载，要么给固定高度再懒加载。Mac 侧栏两区是例外：几十行、行高固定，换页只重算选中变了的行，懒加载实测不省（`Sidebar`）。任务面板的顶层任务多到一屏放不下（`TasksPanel.lazyFrom`）时行按需建、面板定高，不多时由内容撑开（懒加载栈在高度跟着内容变时会漏画）。分批加行不行：每批都把整列再量一遍。会话的对话是例外（只排最近几条、往上翻快到头再排开一段，见 `ChatScroll`）：懒加载栈配底部锚定时，跟随最新会空白、看历史会被带走（iOS 27 实测）。已排开的按段比较、不重排；离屏远的段换成量好的那么高的空白（`PiConversation.segment`），挂着的视图不随翻过的深度变多，排开一段从约 50 轮到第 1 轮都在 100ms 上下（iOS 27 模拟器，`-CuePadBench chatdepth` 量）。不封顶地挂着时 300 轮处要 200ms 以上；只挂几段、两头卸掉的做法要同时补偿上下两头的高度差，补偿时序跟滚动区配不上，会卡在半途。
- 每天开很多次、建起来又贵的浮层（⌘K）常驻：启动后空闲时挂上、收起只是透明、点不到、停用、暂停订阅（`keptPanel`），收起时清掉查询与结果；其余浮层开时才建。工具栏里内容多的菜单（项目切换）同理常驻，不随侧栏开合增删，标签只在收起时写当前页（标签一变整份菜单跟着重建）。
