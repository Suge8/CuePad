# 界面约定

跨界面的原则与理由。具体界面的样子与规则在各视图类型的头注释里；颜色令牌在 `Palette`，字号、间距、动效与表面在 `UI/Shared/Theme/`。能写成检查的规则在 `apple/scripts/lint.sh`，原因写在它的报错里。

做新界面或视觉改动时，先读 ui-craft 与 ui-picks 两个 skill，先出原型或截图给用户看，再出文字方案。

## 视觉原则

- 内容是纸，控件是玻璃：灵感与任务的卡片是纸色实底；工具栏、侧栏、弹层、菜单栏面板用系统 Liquid Glass，玻璃不叠玻璃。用户靠这个一眼分清内容和操作。
- 颜色只有一份 `Palette`，纸与墨、签名色、状态色、项目色各管什么写在它的头注释里。每多一档颜色，就多一样要用户分辨的东西。
- 石绿有两种用途：会话有新回复，与任务做完（完成对勾、看板已完成那一列）。两者说的都是"这一轮做完了，结果在那儿"，一个落在会话上、一个落在任务上，同一屏里读不混；不再给第三种事。
- 字是墨，分三档（`ink`、`ink2`、`ink3`），三档都是要读的字，在各层底与实底玻璃上都 ≥ 4.5:1；不用系统灰与系统占位色。
- 签名色靛青只给焦点与正在发生的事，一屏一两处。在跑与选中都是"这里有动静"，靠形状分：在跑是会动的线，选中是一块底。
- 项目色只上图形，不写成字、不做成圆点：圆点和彩字会被读成状态。
- 同一状态处处同一个样子，用户只学一次。每种图形只有一个出处：任务圈 `TaskRingView`（有步骤的按步骤分段，步骤做到哪只画在圈上、不另写"n/m"）、任务行 `TaskLine`（项目页与任务看板同一种行，要你管的才写状态词）、会话状态 `PiShown`、出错 `FailureMark`、等你 `Waiting.swift`；新界面引用它们，不另画。对勾只表示完成与记下。
- 图标只经 `Icon`，品牌标志只经 `BrandMark`，规则在各自头注释里。"发出"（发送钮、发送回答、交给）是纸飞机，只表示方向的（在上面、更早的、回到最新）是燕尾箭，两族不互借。系统菜单里的标志要显式标为可见：macOS 27、iPadOS 27 起默认藏起菜单项图片。
- 对话里只有说的话是一块（气泡），块只另给要你操作的卡片（等你、启用）；其余是不铺底、不描边的旁注与居中标记（`ChatMargin.swift` 头注释）。一眼分得出哪句是对你说的。
- 写着字的玻璃垫实底（`GlassInk.solid`）：内容滚到玻璃后面，背后可能是亮图也可能是深色代码块，只着色的玻璃上字读不出来；垫了底才在任何背景上都够 4.5:1。
- 动效告诉用户东西去了哪，不是表演：位移与尺寸用无回弹弹簧、不超过 300ms，唯一例外是 Cue 与会话之间的接力（`CueRelayStage`）。数值与减弱动态效果的规矩在 `Motion`。
- Mac 照原生控件：按下即变淡、不缩放不震动（`PressFeedback`）；指针照 HIG 与访达、邮件，按钮、行与卡片都是箭头，手形只给打开网页的链接（手形在 Mac 上读作"这是网页"）；单击选中、双击打开的列表两种点按并列识别，单击不等双击间隔。和系统应用不一样的地方，用户会觉得是坏了。
- 悬停：点得到的东西指针一过就有回应（同 macOS 26 工具栏的玻璃钮、Linear、Arc）——自绘的按钮浮一层淡底、卡片亮一档、行铺淡底，淡入淡出、不挪位置不缩放；只经 `PressStyle`（按种类 `Press`）与 `RowStyle`，自绘的可点控件不用 `.plain`、`.borderless`（`lint.sh` 查），悬停时要换颜色、露记号的按钮读 `buttonHovered`，不各自挂 `onHover`；浮在内容上的玻璃胶囊与圆钮只经 `ControlButtonStyle`（`glass`、`circular`）。系统控件的悬停与焦点环交给系统；iPad 的指针同一套（行同 Mac，按钮用系统的悬停效果）。
- 悬停、选中时才出现的东西不改动周围的排版：悬停才露的操作只经 `hoverReveal` 浮在行上，随选中变的只换颜色与字重、不插不撤占位置的东西。露出一个钮挤动了标题与时间、选中一页让整列侧栏上下跳，都是用户能一眼看见的抖。
- 列表行的选中、按下与悬停底只有 `RowStyle` 一份，调用处只说"这是一行"，不自己画底、圆角与负边距。
- 界面不解释内部规则（分组依据不写成给用户看的说明）：用户要的是现状与下一步。叫法见 WORDS.md。

## 布局约束

- 工具栏内容只随用户操作与数据变化，不随滚动位置、尺寸等布局读数变化。几何读数（`onGeometryChange` / `onScrollGeometryChange`）不写回影响自身排版的状态；按宽度切换排版用 `Layout` 或 `ViewThatFits`。违反会形成布局反馈环，`layout-stress.sh` 抓这类环。
- 手机输入框里的选择菜单用 `MenuButton`，不用 SwiftUI 的 `Menu`：菜单一开键盘变矮，输入框会掉下去再弹回（理由在它的头注释）。
- 读库的修饰符（`observing`）挂在一个真的视图上，读不出来时可以是 `Color.clear`：订阅等视图出现才启动，什么都不排它就不启动，页面永远空白。
- 顶栏的工具栏项在推入时就建好、之后只换内容，控件随数据置灰而不出现消失：推入转场期间系统不重建工具栏项，换项要等转场结束才显示，标题会晚到近一秒。
- 主导航的结构只有一份 `SidebarOutline`，各端只管长相。窄屏（iPhone 与窄窗口 iPad）打开就是 Cue，底部那一排整个窗口一份（`DockRoot`）：项目、任务、会话三格，加占两格的 Cue 钮，扫一眼就知道几件推进中、几件等你；Cue 是主入口，在 Cue 页上 Cue 钮长成输入框、三格收成"⋯"。
- 页面顶上不写大标题：侧栏或底部那一排的选中格已经说了在哪一页。Mac 不另起页顶那一排：Workspace 里已有的状态（项目范围、新任务）收进窗口最顶那一排的工具栏，常驻、固定宽度、只换内容（`ScopeSlot`：工具栏项增删或变尺寸整条重排，实测占切页的三成到一半；工具栏读不到页面的数据，抄过去就是第二个事实源），状态归页面的控件（会话页的搜索、额度环）留在页里，其余操作在右上"⋯"；手机的顶栏每页同一个规则（推入页见 `floatingHeader`，根页见 `DockRoot`），不放状态图标与搜索框以外的输入。根页顶栏的中间只放这一页的范围：任务页与会话页是项目范围（两页共用一份 `Workspace.projectScope`，换页不丢），会话页那颗再接额度环，书架空着。
- 手机与 iPad 上从顶栏长出的面板（Cue 页头、会话页的额度）只有 `GrowPanel` 一种：同一块玻璃原地长大，点外面收回。Mac 上开合不逐帧长大（下面"Mac 上开合"那条），额度明细是从额度环长出的气泡。
- 设置各端同一套分组与说法，按要紧排；一项设置只在一处改：用哪个 Agent 与模型只在 Cue 页上。
- 沉浸式的栏：栏与页顶上那一排钉在顶上、浮在内容上，内容滚到它们后面；栏后面、栏下面不加任何遮罩、渐变、模糊或底色，只在窗口最顶那一条（状态栏、工具栏）垫页底色的渐变，用户定的，撤回过两次；规矩在 `Bars`。
- Mac 上不用 NSWindow sheet、`NSAlert`、`runModal`（`lint.sh` 查）：开、关都把主线程关在约 300ms 的嵌套循环里。窗口内的浮层只有 `panel`，确认框是 `dialog`；关法、模态与焦点交还在 `Panel+macOS.swift`。
- 气泡（`PanelStyle.bubble`）只有两种来源（`BubbleSource`），摆法一份（`BubblePlacement`）：从控件（按钮、圆钮、胶囊）弹出的挂在控件的框上（Mac 用 `bubble(isPresented:)`，控件自己量框），点、键盘、读屏打开都在同一处；从一行里点开的（任务行）用按下的那一点、按行高让开整行，行成百上千，不给每行挂几何读数。都没有时在窗口上方居中。
- 看一条任务只有任务气泡（`TaskBubble`），Mac 上也不用系统 popover：它是另一扇窗，进程里第一次弹要 85～113ms，关时主窗口重新变回前台窗口，开着时主窗口的快捷键不响应；窗口内的气泡开约 30ms、关 5～7ms（实测）。
- Mac 上开合不逐帧挪位置：位置逐帧变时 AppKit 每帧重排整窗、重算鼠标跟踪区并重设光标，会掉帧十几次。侧栏开合一步到位，编辑页原地淡入淡出；有字的一块进出场不缩放（理由在 `Bubble.swift`）。

## 加载与同步

- 本机库里的东西第一帧就是读到的样子，没有"还没读到"这一态：不给页面加"读到没有"的标志、默认值与转圈（`observing`）。要等的只有别的设备。
- "这一页在等同步"只有 `AppServices.isCatchingUp` 一个来源，样子只在 `Pending`。一闪而过的指示比稍等更扰人，所以过了 `Pending.delay` 才出。
- 对同步期间到的新内容先不动正在看的，对完一次滑上来（`ChatScroll` 的 `holding`）。

## 渲染性能约束

实测数字与细节在各类型的注释里；这里是原则。

- 滚动时每帧都变的读数（偏移）不进状态，只放会让状态改变的越线；行里不放 `GeometryReader`。每个几何读数都是一次布局回调，挂在每行上滚动就跟不上。
- 行数不封顶的列表用懒加载栈，懒加载栈里一组行的容器也要懒加载：普通栈打开时把所有行量一遍。例外各在其类型里说明（Mac 侧栏、会话对话）。
- 按时刻换字的文字经 `LiveText`，分段的长文字经 `Paragraphs`，输入框的高度经 `ComposerHeight`：开销与理由在各自头注释里。输入框每敲一个字的开销不随草稿长度增长：不拿整串比较、不重设整篇的属性，草稿的读者（预览、是否命令）只看开头。
- 卡片上不用渐变描边：CPU 按整张卡面积铺渐变，卡片一变宽整面墙重画。渐变只用在填充上。
- 大容器（主窗口）的视图体与灵感墙的每一格不读开合这类频繁变化的整窗状态，读它的部分拆成小视图。
- 第一次打开页面的那一帧只建看得见的：`ViewThatFits` 会把挑剩的候选也建出来，能按尺寸定的用 `Layout` 一次排；`Canvas` 第一次画一张就要几毫秒，几道线、一个环用 `Shape`；打开后紧接着的重活等这一帧画上屏（`NextFrame.drawn`）。
- 先排后动：会动的过渡里，重活（建页、建编辑器、让编辑器接过键盘）放在动之前、每帧一步，动起来之后每帧只剩动画与改透明度。
- Pi 状态的变化是最常见的整树重算来源：视图读自己要的那个会话（`pi.session(sessionID:)`），只关心有哪些会话读 `pi.slots`，读 `pi.sessions` 的只有必须看全部状态的地方；会话行与侧栏项目行是 `Equatable` 的，调用处挂 `.equatable()`。
- 每天开很多次、建起来又贵的浮层常驻，收起只是隐藏（`keptPanel`）；其余浮层开时才建。
- 列表行里成百上千的小点按目标在 Mac 上不用 `Button`，用 `ListPress`。
